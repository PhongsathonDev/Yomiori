# เทียบเว็บปัจจุบันกับต้นแบบ v2

เอกสารนี้สรุปสิ่งที่เห็นจากภาพและตัวเลขที่วัดได้ ยัง **ไม่ใช่คำตัดสินว่า v2 ดีกว่า** — ผู้ใช้ต้องลองใช้งานจริงและเลือกว่าจะใช้ v2 ปรับต่อ หรือคงเว็บเดิม (HITL ใน WF-0035)

## วิธีเทียบ

- ข้อมูลชุดเดียวกัน: `kyudo-senpai` ตอน `ch-01`, ปก/ภาพ/ชื่อไทยยาว/เนื้อหาจริงชุดเดียวกัน
- จอ desktop 1440×900 และ mobile 390×844
- ภาพ before จากเว็บปัจจุบัน (`reader-web` dev server), ภาพ after จากต้นแบบ static
- ธีม Light Muji / Dark Sumi / Warm Hinoki ใช้ชื่อและเจตนาเดิม
- วัด DOM nodes, ความสูงเอกสาร และเวลาโหลดจาก Performance API ในรอบเดียวกัน; เวลาโหลดเป็นเพียงสัญญาณเบื้องต้น เพราะ before เป็น dev server และ after เป็น static server ไม่ใช่ benchmark production

## ภาพเทียบ

อยู่ใน [evidence/](evidence/) ใช้ชื่อ `before-*` และ `after-*` คู่กัน

| หน้า | Desktop | Mobile |
| --- | --- | --- |
| ชั้นวาง (light/dark/sepia) | `shelf-light`, `shelf-dark`, `shelf-sepia` | `shelf-light`, `shelf-dark` |
| รายละเอียดเรื่อง | `detail-light` (full page) | `detail-light` |
| หน้าอ่าน (light/dark/sepia) | `reader-light`, `reader-dark`, `reader-sepia` | `reader-light`, `reader-dark` |
| ตั้งค่าการอ่าน | `settings-light` | `settings-light` |

ภาพเป็น `.jpg` คุณภาพ 85 เพื่อให้ repo ไม่ใหญ่เกินไป; จุดที่ต้องดูคือโครงหน้า การอ่านชื่อไทยยาว และการจัดวางบนจอเล็ก ไม่ใช่รายละเอียดพิกเซลระดับพิมพ์

## ตัวเลขที่วัดได้

| หน้า | DOM nodes (before → after) | ความสูงหน้า desktop | ความสูงหน้า mobile |
| --- | --- | --- | --- |
| ชั้นวาง | 260 → 111 (−57%) | 1,521 → 1,277 px | 3,795 → 1,973 px (−48%) |
| รายละเอียด | 1,568 → 452 (−71%) | 6,350 → 3,894 px | 17,225 → 6,588 px (−62%) |
| หน้าอ่าน | 644 → 220 (−66%) | 7,312 → 5,039 px | 10,354 → 7,163 px |

เวลาโหลดที่บันทึกไว้อยู่ใน `evidence/metrics.json` แต่ตัวเลขแกว่งตาม cache/เครื่อง จึงไม่ใช้สรุปประสิทธิภาพ production ข้อที่มั่นใจได้คือจำนวน DOM และความยาวหน้าที่ลดลงชัดเจน

## ข้อสังเกตด้านหน้าตาและการใช้งาน

**ชั้นวาง**

- before: การ์ดขนาดใหญ่ 3 คอลัมน์บน desktop และ 1 คอลัมน์บนมือถือ แต่ละเรื่องมี synopsis, tag, ปุ่ม 2 ปุ่ม และพื้นที่ว่างจำนวนมาก; เห็นเรื่องได้ไม่กี่เรื่องต่อจอ
- after: ชั้นหนังสือ 5 ปกบน desktop และ 2 ปกบนมือถือ เห็นชื่อเรื่องและสถานะอ่านได้เร็วขึ้น; ปกวางบนเส้นชั้นไม้บางๆ และไม่มีกรอบ card ซ้ำ
- แลกเปลี่ยน: after แสดง synopsis น้อยลงในชั้นวาง ต้องเปิดรายละเอียดเพื่ออ่านเรื่องย่อ

**รายละเอียดเรื่อง**

- before: เรื่องย่อ + การ์ดตอน 3 คอลัมน์ พร้อมปุ่มทุกตอน; หน้าค่อนข้างยาวและมีกรอบซ้ำ
- after: หน้าหนังสือสองคอลัมน์ (ปก + ข้อมูล) แล้วตามด้วยสารบัญแบบตารางพิมพ์ ค้นหา/สลับลำดับได้; ภาพรวมตัวละครและภาพประกอบอยู่ในหน้าเดียว
- แลกเปลี่ยน: after ไม่มีปุ่ม "อ่านตอนนี้" ในทุกแถวตอน ผู้ใช้ต้องคลิกแถวตอนหรือปุ่มอ่านต่อด้านบน; ลดความซ้ำแต่ต้องเรียนรู้เล็กน้อย

**หน้าอ่าน**

- before: header มีปุ่มเยอะ, banner ตอนเป็นการ์ด, บทสนทนาเป็นการ์ดพร้อม avatar/role, มีคอมเมนต์ท้ายตอน
- after: header บางลง, เปิดตอนแบบหน้ากระดาษ, เนื้อหาความกว้างจำกัด, บทสนทนาเป็นแถบสี/ชื่อผู้พูดที่เบาลง, ไม่มีคอมเมนต์
- after ตั้งค่าเริ่มต้นเป็น serif เพื่อการอ่านยาว แต่เปลี่ยนเป็น Looped/Plex ได้; ขนาด/ระยะบรรทัด/รูปแบบบทสนทนาปรับได้ทันที
- แลกเปลี่ยน: after ไม่มีคอมเมนต์และเครื่องมือแก้ไข ซึ่งอยู่นอกขอบเขตตัวอย่างนี้

**จอเล็ก**

- before: การ์ดนิยายเต็มความกว้างทำให้ต้องเลื่อนยาวมาก (ชั้นวาง 3,795 px, รายละเอียด 17,225 px)
- after: ชั้นวาง 2 คอลัมน์ทำให้เห็นปกมากขึ้น, ตัวกรองเป็นแถวเลื่อนแนวนอน, header กระชับ, หน้าอ่านเหลือปุ่มสารบัญ/ธีม/ตั้งค่าแบบ icon
- after ยังคงซ่อน wordmark บางส่วนบนมือถือเพื่อให้ปุ่มมีที่พอ; ตรวจที่ 390 px แล้ว ไม่พบ overflow แนวนอน

**ธีม**

- ทั้งสามโหมดยังใช้กระดาษวาชิ/ถ่าน/ซีดาร์และ accent ดินเผา/ฮิโนกิเดิม
- after ปรับ contrast ของข้อความรองและปุ่มให้ผ่าน AA: ข้อความรอง light 4.58:1, dark 5.46:1, sepia 4.54:1; ปุ่ม dark ใช้ตัวอักษรเข้มบนพื้น salmon เพื่อไม่ให้ขาวบนส้มจาง
- ภาพ sepia ของ after เข้มขึ้นเล็กน้อยเพื่อให้ accent อ่านง่าย

## Accessibility และคุณภาพโค้ด

- Lighthouse (in-app browser) ของ after: Accessibility **1.0**, Best Practices **1.0**, SEO **1.0** ทั้งชั้นวางโหมด dark และหน้าอ่านโหมด light — ไฟล์ `evidence/lighthouse-shelf-after-dark.json`, `evidence/lighthouse-reader-after-light.json`
- มี focus-visible, skip link, `aria-*`, dialog แบบ `aria-modal` + `inert`, ปิดด้วย Esc, focus trap, `prefers-reduced-motion`
- ตรวจข้อมูล/ภาพ/ลิงก์/ฟอนต์ด้วย `tools/check.mjs` ผ่าน; `node --check` ผ่าน
- ยังไม่ได้ทดสอบ Safari/Firefox จริง และยังไม่ได้ทำ automated E2E

## ข้อจำกัดที่ต้องบอกผู้ใช้

- ต้นแบบอ่านอย่างเดียว ไม่มีคอมเมนต์ โหมดแก้ไข หรือการซิงก์ความคืบหน้า
- ข้อมูลเป็น snapshot; ตอนใหม่ในเว็บจริงจะไม่ปรากฏจนกว่าจะ build data ใหม่
- ภาพก่อน/หลังเป็นคนละ environment (dev vs static) จึงใช้เทียบหน้าตา/โครงสร้าง ไม่ใช่ตัดสินความเร็ว production
- ยังไม่มีการทดสอบกับผู้อ่านจริงหรืออุปกรณ์จริงนอก Chrome; HITL ต้องเป็นผู้ตัดสิน

## คำถามที่ขอให้ผู้ใช้ตอบหลังลอง

1. โดยรวมชอบโครงชั้นวาง/หน้าอ่านแบบ v2 หรือเว็บเดิมมากกว่า เพราะอะไร
2. อยากให้ปรับจุดใดก่อน (เช่น ปกใหญ่ขึ้น, เนื้อหาอ่านสบายขึ้น, สารบัญสั้นลง, เก็บปุ่มด่วน)
3. ต้องการให้ต้นแบบรวมคอมเมนต์/โหมดแก้ไขเพื่อเทียบครบ หรือพอสำหรับตัดสินหน้าตา
4. ถ้าจะไปต่อ ให้ยืนยัน "ตัวอย่าง v0.1 นี้ใช้เป็นฐานพัฒนาได้" หรือระบุรุ่นที่ต้องการให้ปรับก่อน
