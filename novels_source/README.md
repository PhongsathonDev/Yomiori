# มาตรฐานการดึงนิยายจาก Nekopost

เอกสารหลักสำหรับคนและ AI ที่ดึงนิยายจาก Nekopost มาเก็บใน `novels_source/` เพื่อให้ทุกเรื่องมีโครงสร้างเดียวกัน ตรวจสอบย้อนกลับได้ และไม่สูญเสียข้อความหรือภาพประกอบ

**อ่านเอกสารนี้ก่อนดึงเรื่องใหม่หรืออัปเดตต้นฉบับทุกครั้ง** สคริปต์ช่วยรักษาทะเบียนและจัดรูปแบบ แต่ยังต้องตรวจความตรงของเนื้อหากับต้นทางตามหัวข้อ 8 ไม่รับรอง zero-loss จาก exit code เพียงอย่างเดียว

## 1. ขอบเขตและหลักการ

- `novels_source/` เป็นคลังต้นฉบับ ไม่ใช่ข้อมูล JSON สำหรับแอป ห้ามเขียนสรุปหรือฉบับเรียบเรียงแทนต้นฉบับ
- เก็บเฉพาะเนื้อหาที่มีสิทธิ์เข้าถึงและจัดเก็บ เคารพข้อกำหนดเว็บไซต์และเจ้าของผลงาน การเข้าถึงได้ไม่ได้แปลว่ามีสิทธิ์เผยแพร่ซ้ำ
- คงชื่อเรื่อง ชื่อตอน เครดิตผู้แต่ง/ผู้วาด/ผู้แปล ลำดับตอน และเนื้อหาตามแหล่งที่มา ห้ามเดาข้อมูลที่ไม่มีหลักฐาน
- การดึงต้นฉบับอย่างเดียว **ไม่ใช่การนำเข้าคลังอ่าน** และห้ามรายงานว่าแอป/CDN มีตอนใหม่แล้ว หากนำเข้า reader ด้วย ต้องทำครบ 6 ขั้นตอนใน [AGENTS.md](../AGENTS.md) และ [AI_CONVERSION_GUIDE.md](../AI_CONVERSION_GUIDE.md)
- ไม่ปรับชื่อหรือย้ายไฟล์เก่าทั้งคลังเพียงเพื่อให้ตรงมาตรฐานใหม่ ตรวจผู้ใช้งานไฟล์และขอขอบเขตการย้ายก่อนเสมอ

## 2. โครงสร้างโฟลเดอร์บังคับ

```text
novels_source/
├── README.md
└── <novel-id>/
    ├── _source.json                  # แหล่งที่มา + ทะเบียนตอนและภาพ
    ├── 00_<ชื่อเรื่องที่ปลอดภัย>.md    # ข้อมูลเรื่อง เรื่องย่อ และสารบัญ
    ├── Ch_00_<ชื่อตอน>.md             # ถ้ามีตอน 0 จริงบนเว็บไซต์
    ├── Ch_01_<ชื่อตอน>.md
    ├── Ch_02_<ชื่อตอน>.md
    └── illustrations/
        ├── illust_01.jpg             # ภาพในตอน 0 ตามลำดับที่ปรากฏ
        └── ch02_img1.webp            # ภาพแรกในตอน 2
```

- `<novel-id>` ใช้อักษรอังกฤษพิมพ์เล็ก ตัวเลข และขีดกลาง เช่น `black-cat-hangout` ต้องตรงกับ slug เดิมถ้ามีเรื่องนั้นแล้ว ห้ามใช้ช่องว่างหรือส่วนของ path เช่น `../`
- ใช้ `novels_source/` เป็นคลังต้นฉบับเพียงแห่งเดียว วางไฟล์ตอนตรงใน `novels_source/<novel-id>/` ไม่สร้างโฟลเดอร์รับเข้าชั่วคราวหรือโฟลเดอร์ซ้อนสำหรับไฟล์ตอน
- หนึ่งเรื่องต่อหนึ่งโฟลเดอร์ หนึ่งรายการตอนบนเว็บไซต์ต่อหนึ่งไฟล์ Markdown; ไม่รวมหลายตอนเป็นไฟล์เดียว และไม่สร้าง `.txt` ซ้ำเป็นต้นฉบับอีกชุด
- บันทึกข้อความเป็น UTF-8 ใช้ LF และปิดท้ายไฟล์ด้วย newline; `_source.json` ใช้ JSON ถูกต้องและเยื้อง 2 ช่อง
- `CONVERSION_STATUS.md` และ `visual-assets.md` เป็นเอกสารเสริมตามความจำเป็น วางในโฟลเดอร์เรื่องเดียวกันได้ แต่ไม่ใช่ไฟล์ตอน; เครื่องมือต้องเลือกเฉพาะไฟล์ชื่อขึ้นต้น `Ch_` หรือรูปแบบเก่า `Ch.` ไม่อ่าน Markdown ทุกไฟล์เป็นตอน

## 3. ชื่อไฟล์และเลขตอน

1. ใช้ `Ch_<เลขตอน>_<ชื่อตอนที่ปลอดภัย>.md` เติมศูนย์สำหรับเลขจำนวนเต็มหลักเดียว เช่น `Ch_01_...md`; ตอน 100 ใช้ `Ch_100_...md` ไม่ตัดเลข
2. คงเลขตอนจริง รวมตอน 0 ตอนพิเศษ ตอนประกาศ และเลขทศนิยม เช่น `84.5` ห้ามเปลี่ยนเป็นเลขเรียงใหม่ ห้ามสร้างตอนเติมช่องว่างที่เว็บไซต์ไม่มี
3. ถ้าต้นทางมี **เลขตอนซ้ำ** หลายรายการ (เช่นตอน `40` สองตอนที่เป็นคนละเนื้อหา) ให้เก็บทุกรายการตามเลขเดิม แยกด้วย `chapterId` และชื่อไฟล์ที่ต่างกันจากชื่อตอน ห้ามตัดตอนทิ้งหรือตั้งเลขใหม่เอง และต้องบันทึกเหตุผล/เลขที่ซ้ำไว้ใน overview
4. เลขตอน (`chapterNo`) ไม่ใช่รหัสภายใน (`chapterId`) เช่น URL `/novel/17903/1` ใช้เลขตอน `1` ไม่ใช่รหัสภายใน `244400`
5. ทำชื่อไฟล์ให้ปลอดภัยตาม `sanitizeFileName` ใน [scrape-nekopost.js](../scripts/scrape-nekopost.js): แทน control characters ด้วยช่องว่าง แทน `\ / : * ? " < > |` ด้วย `_` ยุบช่องว่าง และตัดจุด/ช่องว่างท้ายชื่อ
6. สคริปต์จำกัดส่วนชื่อตอนไว้ 90 หน่วย UTF-16 และ 190 ไบต์ UTF-8; ชื่อเรื่องในไฟล์ `00_` จำกัด 80 หน่วยและ 194 ไบต์ อย่าตัด UTF-8 กลางตัวอักษร ตรวจชื่อไฟล์เต็มไม่เกิน 200 ไบต์ตามเครื่องมือตรวจของ repo และตรวจ path บน Windows ด้วย
7. ตัดทอนเฉพาะ **ชื่อไฟล์** เมื่อยาวเกินไป ชื่อเต็มในหัว Markdown และ `chapterName`/`projectName` ต้องไม่ถูกตัดตาม
   - ถ้าชื่อจริงมีแต่จุด เช่น `.....` จนชื่อไฟล์หลัง sanitize ว่าง ให้ใช้ `Ch_<เลขตอน>_chapter-<chapterId>.md` เฉพาะชื่อไฟล์ โดยคงชื่อจริงในหัว Markdown และ `chapterName`; ไม่ใช้กฎนี้แทนชื่อตอนที่ต้นทางไม่มีข้อมูล
8. ถ้าชื่อตอนเปลี่ยน ให้จับคู่ด้วย `chapterId` และตรวจ `chapterNo` ก่อน สคริปต์คงชื่อไฟล์เดิมเพื่อไม่ให้ลิงก์พัง; ใช้ `--force` เฉพาะตอนเพื่ออัปเดตหัวเรื่อง/metadata/เนื้อหาเมื่อยินยอมเขียนทับแล้ว หากจะเปลี่ยนชื่อไฟล์ด้วยต้องอัปเดตทุกลิงก์พร้อมกัน ห้ามเหลือสองไฟล์แทนตอนเดียวโดยไม่ตั้งใจ

## 4. รูปแบบไฟล์ตอน

ใช้ส่วนหัวตามผลลัพธ์ของสคริปต์เดิม เพื่อให้เครื่องมือแปลงแยกเครดิตออกจากเนื้อเรื่องได้:

```markdown
# Ch.1 — ชื่อตอนเต็มตามต้นทาง

Ch.1 — ชื่อตอนเต็มตามต้นทาง

By ชื่อผู้แปลหรือผู้เผยแพร่ตามต้นทาง

Published: 2026-10-29T08:00:00Z

Source: https://www.nekopost.net/novel/12345/1

ย่อหน้าแรกตามต้นฉบับ

“บทสนทนาตามต้นฉบับ”

![Illustration](illustrations/ch01_img1.jpg)

ย่อหน้าถัดไปตามต้นฉบับ
```

- หัวเรื่องสองบรรทัดข้างต้นเป็นรูปแบบที่สคริปต์เดิมสร้าง ไม่ใช่ย่อหน้าเนื้อเรื่องเพิ่ม; เครื่องมือแปลงต้องไม่รวมส่วนหัว/เครดิต/URL เป็นเนื้อเรื่อง
- `Source:` บังคับและต้องตรงกับตอนนั้น ส่วน `By` และ `Published` ให้ละบรรทัดเมื่อไม่มีข้อมูล ห้ามแต่งเครดิตหรือวันที่ขึ้นเอง
- รักษาทุกย่อหน้า บทสนทนา ข้อความในใจ เครื่องหมายคำพูด จุดไข่ปลา เส้นแบ่งฉาก เชิงอรรถ และหมายเหตุผู้เขียน/ผู้แปลตามลำดับเดิม รวมข้อความหลังภาพและท้ายตอน
- เว้นบรรทัดระหว่างย่อหน้า ไม่ตัดข้อความเป็นบรรทัดตามความกว้างหน้าจอ ไม่แก้คำผิด เปลี่ยนสำนวน สรุป เซ็นเซอร์ หรือเติมคำอธิบายในเนื้อหา
- นำเมนู โฆษณา ปุ่มเปลี่ยนตอน รายการแนะนำ และคอมเมนต์ผู้อ่านซึ่งอยู่นอกเนื้อหาตอนออกได้ แต่ห้ามลบหมายเหตุผู้แปลหรือประกาศที่เป็นส่วนหนึ่งของตอน
- แปลง HTML entities เป็นอักขระที่แสดงจริง และแปลง `<p>`/`<br>` เป็นการแบ่งข้อความโดยไม่ทำคำติดกัน รักษาความหมายของตัวเอียง ตัวหนา ruby และตารางเมื่อมี; ถ้าตัวดึงทำรูปแบบสำคัญหายให้ตรวจและแก้ก่อนรับงาน
- ลบหัวเรื่องที่ซ้ำใน body ได้เฉพาะเมื่อเทียบแล้วเป็นหัวเดียวกับหน้าตอนจริง ห้ามลบทุกบรรทัดที่ขึ้นต้นว่า “บทที่” โดยอัตโนมัติ

## 5. ข้อมูลแหล่งที่มาและสารบัญ

### `_source.json`

ใช้ชื่อ key ตามสคริปต์ปัจจุบัน ตัวอย่างต่อไปนี้เป็น **ข้อมูลสมมติสำหรับอธิบายรูปแบบ**:

```json
{
  "source": "nekopost",
  "projectId": 12345,
  "projectName": "ชื่อเรื่องเต็มบน Nekopost",
  "originalTitle": null,
  "originalUrl": null,
  "author": null,
  "artist": null,
  "status": null,
  "categories": [],
  "synopsis": "เรื่องย่อตามต้นทาง",
  "scrapedAt": "2026-10-29T08:00:00.000Z",
  "totalChapters": 1,
  "chapters": [
    {
      "chapterNo": "1",
      "chapterId": 234567,
      "chapterName": "ชื่อตอนเต็มตามต้นทาง",
      "provider": "ชื่อผู้แปลตามต้นทาง",
      "publishedAt": "2026-10-29T07:00:00Z",
      "url": "https://www.nekopost.net/novel/12345/1",
      "file": "Ch_01_ชื่อตอนเต็มตามต้นทาง.md",
      "images": [
        {
          "source": "https://example.org/original-image.jpg",
          "file": "illustrations/ch01_img1.jpg"
        }
      ]
    }
  ]
}
```

- `projectId` และ `chapterId` เป็นรหัสจากต้นทาง; `chapterNo` เก็บเป็น string ตามต้นทางเพื่อรักษาเลขทศนิยม ไม่ใช้ `parseInt` ตัดเศษ
- `originalUrl` คือแหล่งผลงานต้นฉบับถ้ามี ไม่ใช่ URL ของ Nekopost; URL ตอนอยู่ใน `chapters[].url`
- ข้อมูลที่ไม่ทราบใช้ `null`, รายการใช้ `[]`, เรื่องย่อที่ไม่มีใช้ `""`; ไม่สร้างข้อเท็จจริงทดแทน และคงค่า `status` ดิบโดยไม่ตีความเลขเอง
- `scrapedAt` คือเวลา UTC แบบ ISO 8601 ของการดึงรอบนั้น ไม่ใช่วันเผยแพร่; `publishedAt` เก็บค่าจากต้นทาง ไม่เดา timezone ที่ไม่มีระบุ
- `totalChapters` คือจำนวน **รายการตอนที่ต้นทางแจ้ง** รวมภาพประกอบ/ประกาศถ้าอยู่ในรายการ ไม่ใช่เลขตอนสูงสุด และไม่ใช่จำนวนตอนที่แปลงเข้าแอปแล้ว
- `chapters` คือทะเบียนไฟล์ที่จัดเก็บจริง เรียงตามลำดับตอน ห้ามซ้ำ `chapterId` หรือมีหลายไฟล์สำหรับตอนเดียวโดยไม่อธิบาย ทุก `file` ต้องมีอยู่จริงใน `novels_source/<novel-id>/` โดยตรง
- `chapters[].file` เป็นชื่อไฟล์อย่างเดียว ส่วน `images[].file` เป็น path จากรากโฟลเดอร์เรื่อง ใช้ `/` ไม่ใช้ absolute path หรือ `\`
- ถ้าดึงเพียงบางตอน `chapters.length` อาจน้อยกว่า `totalChapters` ได้ แต่ต้องระบุขอบเขตและตอนที่ขาดใน overview/รายงานอย่างชัดเจน ห้ามอ้างว่าครบทั้งเรื่อง

### `00_<ชื่อเรื่องที่ปลอดภัย>.md`

ต้องมีชื่อเต็ม ข้อมูลต้นฉบับ/เครดิต ลิงก์หน้า Nekopost แนว สถานะเท่าที่ทราบ วันที่ดึง เรื่องย่อตามต้นทาง และ `## สารบัญ` พร้อมลิงก์ไปยังไฟล์ที่มีจริง เรียงลำดับตรงกับ `_source.json`

แยก “จำนวนรายการบนต้นทาง”, “จำนวนที่เก็บแล้ว” และ “ขอบเขต/รายการที่ยังขาด” ให้ชัดเจน สารบัญลิงก์ไปยัง `<ชื่อไฟล์>` ในโฟลเดอร์เดียวกันโดยตรง และ encode อักขระพิเศษใน URL เช่น ช่องว่าง วงเล็บ `#` เพื่อให้เปิดลิงก์ได้จริง

สคริปต์อัปเดตเฉพาะเนื้อหาระหว่าง `<!-- nekopost:generated:start -->` กับ `<!-- nekopost:generated:end -->` ให้เขียนบันทึกเพิ่มเติมนอกช่วงนี้ หาก overview เดิมยังไม่มี markers สคริปต์จะรักษาเนื้อหาเดิมไว้ในส่วน “บันทึกจาก overview เดิม” ไม่ลบทิ้ง และไม่เปลี่ยนชื่อ overview เดิมโดยอัตโนมัติ

## 6. ภาพประกอบ

- ดาวน์โหลดภาพจากเนื้อหาตอนโดยคงลำดับและตำแหน่งแทรก ไม่รวบภาพทั้งหมดไปท้ายตอน ไม่ถือว่าตอนภาพประกอบเป็นตอนว่าง
- เก็บภาพใน `illustrations/` ของเรื่อง ใช้ `illust_01`, `illust_02`, ... สำหรับตอน 0 และ `ch<เลขตอน>_img1`, `ch<เลขตอน>_img2`, ... สำหรับภาพแทรกตอนอื่นตามสคริปต์เดิม
- ถ้าเลขตอนนั้นซ้ำกับตอนอื่น ให้เติม `chapterId` หลังเลขตอนเพื่อไม่ให้ภาพทับกัน: `ch40_173299_img1.jpg` (ใช้กับทุกตอนที่เลขซ้ำกัน) และต้องอธิบายใน overview
- เก็บไฟล์ภาพจริง ไม่ใช่หน้า HTML แจ้ง error ตรวจว่าเปิดภาพได้ และนามสกุลตรงชนิดข้อมูล ไม่ย่อ ครอป ใส่ลายน้ำ หรือบีบอัดใหม่โดยไม่จำเป็น
- ใน `_source.json` จับคู่ URL ภาพต้นทางกับไฟล์ local ทุกภาพ; ไฟล์ตอนอยู่ในโฟลเดอร์เรื่องโดยตรงจึงใช้ `illustrations/<ชื่อไฟล์>` ทั้งใน Markdown และ metadata
- ถ้าโหลดไม่ได้ ให้หยุดตอนนั้นและระบุ URL ภาพ/ตอนที่ยังค้างในรายงาน สคริปต์จะไม่ลงทะเบียนตอนนั้นว่าสำเร็จ ห้ามลบภาพเงียบ ๆ หรือรายงานว่าครบออฟไลน์ หากจัดเก็บด้วยวิธีอื่นแล้วคง URL ภายนอกไว้ชั่วคราวต้องบอกว่ายังไม่ครบ
- ปก แบนเนอร์ หรือภาพอ้างอิงนอกเนื้อหาตอนให้แยกชื่อและบันทึกแหล่งที่มาใน `visual-assets.md` ไม่อ้างว่าเป็นภาพแทรกในตอน

## 7. วิธีดึงและพฤติกรรมของสคริปต์

ใช้ Node.js ที่รองรับ `fetch` ในตัว (18 ขึ้นไป; แนะนำรุ่น LTS ที่ยังได้รับการดูแล) และรันจากราก repo ไม่ต้องติดตั้งไลบรารีเพิ่มสำหรับสคริปต์นี้:

```powershell
# รูปแบบคำสั่ง — แทนค่าก่อนรัน
node scripts/scrape-nekopost.js <projectId> <novel-id>

# ตัวอย่างจริงของเรื่องที่มีอยู่แล้ว — ตรวจสถานะและสำรองก่อนอัปเดต
node scripts/scrape-nekopost.js 17903 black-cat-hangout

# เลือกเลขตอน ไม่ใช่ chapterId; ระบุเป็นรายการ ไม่รองรับ 1-3
node scripts/scrape-nekopost.js 17903 black-cat-hangout --only=1,2,3

# บังคับดึงและเขียนทับเฉพาะตอนที่เลือก ใช้เมื่อได้รับอนุญาตให้แทนต้นฉบับแล้ว
node scripts/scrape-nekopost.js 17903 black-cat-hangout --only=1 --force
```

**อย่ารันคำสั่งตัวอย่างทับงานเดิมโดยไม่ตรวจ diff/สำรอง** สคริปต์ [scrape-nekopost.js](../scripts/scrape-nekopost.js) มีมาตรการป้องกันดังนี้ แต่ยังไม่ใช่หลักฐานว่าผ่านการตรวจเนื้อหาครบ:

| พฤติกรรม | สิ่งที่ต้องรู้ |
| --- | --- |
| `--only` เลือกตอนที่จะดึง แล้ว merge ทะเบียนด้วย `chapterId` | ตอนและ image mapping เดิมยังอยู่; `totalChapters` ยังนับรายการทั้งหมดบนต้นทาง และ overview ระบุตอนที่ยังไม่ได้เก็บ |
| ไม่ใช้ `--force` จะข้ามตอนที่ลงทะเบียนแล้ว | ไม่เปลี่ยน body/เครดิต/ภาพของตอนเก่า แม้ชื่อต้นทางเปลี่ยน แต่ยังอัปเดตข้อมูลระดับเรื่องและส่วน generated ใน overview |
| `--force` ดึงซ้ำเฉพาะขอบเขตที่เลือก โดยคงชื่อไฟล์เดิม | ถ้าไม่ระบุ `--only` จะเขียนทับทุกตอนในรายการต้นทาง ห้ามใช้เพื่อแก้ metadata อย่างเดียวโดยไม่ยินยอมแทนเนื้อหา |
| มีไฟล์ตอนอยู่แต่ไม่อยู่ใน `_source.json` | หยุดแทนการเขียนทับแม้ระบุ `--force`; ตรวจและจัดทำทะเบียนที่พิสูจน์แหล่งที่มาได้ก่อน สำหรับคลังเก่าอย่ารันทับเพื่อย้ายรูปแบบ |
| ทะเบียนผิด project, `chapterId` ซ้ำ, ไฟล์/ภาพที่ลงทะเบียนหาย หรือเลขตอนเปลี่ยนตัวตน | หยุดให้ตรวจแก้โดยชัดเจน ไม่เดาการจับคู่หรือทิ้งข้อมูลเก่า; เลขตอนซ้ำจากต้นทางที่มี `chapterId` ต่างกันไม่ถือเป็นความผิดและถูกเก็บทั้งคู่; ตอนที่ต้นทางถอดออกยังเก็บไว้และนับแยกจากจำนวนต้นทาง |
| ลิงก์ภาพใน Markdown ใหม่ใช้ `illustrations/...` และตรวจชนิดภาพจาก signature | ไม่เชื่อเฉพาะนามสกุล URL; รองรับ JPEG/PNG/GIF/WebP/AVIF รูปแบบอื่นหรือภาพที่โหลดไม่สำเร็จจะหยุดให้ตรวจ |
| เนื้อหาตอนอ้างภาพด้วย placeholder `{file_fs}`/`{file_img}`/`{file_audio}` | สคริปต์แทนด้วย CDN ของต้นทาง (`www` หรือ `fs.osemocphoto.com` ตาม `projectId`) แล้วดาวน์โหลดจริง; ถ้าได้ HTML แทนภาพจะหยุด |
| แปลง HTML เป็นย่อหน้า เก็บเส้นแบ่งฉาก และไม่ลบย่อหน้าแรกโดยเดาว่าเป็นหัวซ้ำ | ตัวเอียง/หนาและโครงสร้าง ruby/ตารางยังไม่ได้รักษาเป็น Markdown แบบสมบูรณ์; named entities ที่ไม่รู้จักคงข้อความเดิมไว้ ต้องตรวจรูปแบบพิเศษกับต้นทาง |
| checkpoint หลังบันทึกแต่ละตอน และเขียนแต่ละไฟล์ผ่าน temporary file แล้ว rename | รันซ้ำต่อจากตอนที่ลงทะเบียนสำเร็จได้ แต่ไม่ใช่ธุรกรรมครอบคลุมทั้งชุด; หากไฟดับหรือพังระหว่างเขียนหลายไฟล์ให้ตรวจ diff/ทะเบียน/ภาพก่อนเริ่มใหม่ |
| รักษาบันทึก overview นอก markers และเก็บเนื้อหา legacy ไว้ | เนื้อหาในช่วง generated ถือว่าให้สร้างใหม่ได้ อย่าเขียนบันทึกมือในช่วงนั้น |

การรันซ้ำแบบ skip **ไม่ซ่อมเนื้อหา/ลิงก์ภาพของตอนเก่า** หากคลังเดิมใช้ path ภาพผิดหรือ metadata ภาพหาย ให้ตรวจและแก้เฉพาะรายการที่ได้รับอนุญาต หรือดึงตอนนั้นใหม่อย่างมีขอบเขต ไม่ใช้ `--force` ทั้งเรื่องโดยปริยาย

ดึงแบบเรียงลำดับ ไม่ยิงหลาย process พร้อมกัน สคริปต์เว้นประมาณ 300 ms หลังดึงแต่ละตอน กำหนด timeout 30 วินาทีต่อ request และลองใหม่รวมไม่เกิน 4 ครั้งเฉพาะ network error, HTTP 408 และ 5xx หากพบ 429 จะหยุดพร้อมแจ้ง `Retry-After`; หากพบ 401/403, CAPTCHA หรือการจำกัดสิทธิ์ ให้หยุดและรายงาน ไม่เพิ่มโหลดหรือหลบข้อจำกัด

ตรวจ regression ของตัวดึงโดยไม่เชื่อมต่อเว็บไซต์และไม่แก้ต้นฉบับจริง:

```powershell
node --test scripts/scrape-nekopost.test.cjs
```

สำหรับไฟล์เก่าที่ชื่อยาว มีเครื่องมือ:

```powershell
node scripts/normalize-source-filenames.js novels_source/<novel-id>
```

เครื่องมือนี้ **แก้ไฟล์จริง**: เปลี่ยนชื่อไฟล์/overview และสร้างส่วนสารบัญใหม่จาก `_source.json` โดยรักษา generated markers และหัวข้อถัดไป ใช้เฉพาะเมื่อจำเป็นและสำรองก่อน ไม่ใช่ตัวตรวจแบบ read-only ไม่แก้ลิงก์อ้างอิงนอกชุดไฟล์นั้น และไม่ตรวจความครบของเนื้อหา

## 8. ขั้นตอนทำงานและเกณฑ์ตรวจรับ

### ก่อนดึง

- [ ] ยืนยัน URL แบบ `/novel/<projectId>` ไม่ใช่ `/manga/` และตรวจว่า slug ไม่ชนกับคนละเรื่อง
- [ ] ระบุขอบเขต: ทั้งเรื่องหรือเลขตอนใด รวมตอน 0/พิเศษ/ประกาศหรือไม่; ถ้าไม่ได้ยกเว้นให้เก็บทุกรายการของเรื่อง
- [ ] ตรวจ `git status` และข้อมูลเดิม สำรอง metadata/overview และไฟล์ที่จะเขียนทับ ไม่ทับงานคนอื่น และไม่ใช้ `--force` โดยปริยาย
- [ ] บันทึกรายการตอนต้นทางเพื่อใช้ตรวจจำนวนและเลขตอนหลังดึง รวมเลขทศนิยมและช่วงเลขที่เว้นจริง

### หลังดึง

- [ ] โครงสร้าง/ชื่อไฟล์/encoding ตรงมาตรฐาน และไฟล์เปิดได้บน Windows/GitHub Actions
- [ ] ตรวจชุดรายการตอนตรงตามขอบเขต ไม่ใช้เพียงเลขตอนสูงสุดเป็นหลักฐานว่าครบ; อธิบายตอนขาด/ตอนที่ดึงไม่ได้
- [ ] `_source.json` parse ได้ ทุกไฟล์ที่ระบุมีจริง ไม่มีไฟล์ตอนตกทะเบียน/รายการซ้ำ และสารบัญลิงก์เปิดได้
- [ ] ทุกตอนมีชื่อเต็ม URL ถูกตอน และเครดิต/วันที่เท่าที่ต้นทางมี
- [ ] เทียบเนื้อหาของ **ทุกตอนที่ดึงหรือเปลี่ยน** กับ body ต้นทางครบทุกย่อหน้า ตามลำดับ รวมต้นตอน ท้ายตอน หมายเหตุ และภาพ; อนุญาตเพียงการแปลงรูปแบบ HTML/ช่องว่างที่ไม่เปลี่ยนข้อความหรือการแบ่งย่อหน้า
- [ ] ความยาว/จำนวนอักขระเป็นเพียงสัญญาณเตือน ไม่ใช่หลักฐานความตรง 100%; ไม่อ้างว่า zero-loss จากการสุ่มตรวจหรือจำนวนตัวอักษรใกล้เคียงกัน
- [ ] ภาพครบ เปิดได้ มี mapping ต้นทาง และ path local ถูกต้อง; รายการที่ยังใช้ภาพภายนอกต้องประกาศว่ายังไม่ครบ
- [ ] ตรวจ `git diff` ว่าไม่มีเนื้อหาที่ไม่เกี่ยวข้องหาย และ metadata/สารบัญเดิมยังครบหลังรันซ้ำหรือใช้ `--only`
- [ ] รายงานผลพร้อมหลักฐานที่ตรวจจริง หากตรวจไม่ได้ให้บอกว่ายังไม่ตรวจ ไม่เขียนว่า “ผ่าน” ล่วงหน้า

รายงานส่งมอบอย่างน้อยต้องระบุ **เรื่อง/slug, URL/projectId, ขอบเขต, จำนวนรายการต้นทาง, จำนวนไฟล์ที่เก็บ, จำนวนภาพที่เก็บ, รายการขาดหรือข้อผิดพลาด, วิธีตรวจความครบ และไฟล์ที่เปลี่ยน** จากนั้น commit เฉพาะงานที่เกี่ยวข้องและ push ตามนโยบาย repo ถ้า push ไม่สำเร็จต้องแจ้งตรง ๆ
