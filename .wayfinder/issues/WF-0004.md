## Question

เมื่อไฟล์ตอนในเครื่อง รายการตอนจาก manifest และข้อมูลหนังสือไม่ตรงกัน ควรใช้หลักฐานใดเป็นแหล่งอ้างอิงของคลังออฟไลน์ และตรวจคืนความสอดคล้องอย่างไรเพื่อไม่ซ่อนตอนที่มีอยู่จริง?

เทียบทางเลือก local index, validated file discovery และการใช้ร่วมกัน โดยอิงข้อมูลและรูปแบบไฟล์ของ repo ปัจจุบัน รวมถึงตอนสูงกว่า fallback เดิม หนังสือที่ไม่ได้อยู่ใน bundled catalog ไฟล์เสีย recovery backup และ metadata ที่อ่านไม่ได้ การตัดสินใจต้องรักษาไฟล์ดาวน์โหลดและ progress เดิม และอธิบายผลต่อเวลาเปิดแอปโดยไม่สรุปให้สแกนทุกไฟล์ก่อนแสดงหน้าจอ

เป็นการตัดสินใจร่วมกับผู้ใช้พร้อมข้อเสนอที่มีเหตุผลจากโค้ด ไม่ใช่ implementation ticket หากจำเป็นต้องทราบข้อเท็จจริงภายนอกเพิ่มเติม ให้เปิด research ticket เฉพาะคำถามนั้นตามขั้นตอนของ wayfinder

## Progress comments

### 27 ตุลาคม 2026 — หลักฐานระหว่างลงมือแก้ตาม execution note

Source เพิ่ม validated discovery จากไฟล์ตอนและ recovery backup แล้ว รวมเข้ากับ manifest/catalog โดยไม่ย้ายไฟล์หรือเปลี่ยน progress keys และไม่เก็บ chapter bodies ทั้งคลังไว้ใน memory การเรียก local-only ไม่ตกไปเรียกเครือข่ายเมื่อ metadata หาย ทดสอบกรณีตอนสูงกว่าช่วง fallback, หนังสือที่ metadata หาย, ไฟล์เสียและ in-flight scan แล้ว ดู [storage](../../reader-mobile/src/services/storage.ts), [API](../../reader-mobile/src/services/api.ts), [regression tests](../../reader-mobile/__tests__/offline.test.ts)

ยังไม่ปิด ticket นี้ใน session ที่ resolve ticket สถานะออฟไลน์แล้ว และยังไม่มีผลวัด filesystem บนมือถือจริง จึงไม่อ้างความเร็ว native หรือว่าค่าใช้จ่ายการ scan เหมาะกับทุกขนาดคลัง

## Resolution comments

### 28 October 2026 — Codex

เลือก validated file discovery เป็นแหล่งอ้างอิงของคลังในเครื่อง รวม manifest/bundled summaries โดยไม่ย้ายไฟล์หรือเปลี่ยน progress keys; ไม่เพิ่ม persisted index ก่อนมีผลวัดคลังใหญ่บน Android

รายละเอียดและเกณฑ์รับงานอยู่ใน [Reader Android contract](../assets/reader-contract/spec.md) อิงคำสั่งผู้ใช้ให้ดำเนินงานตามแผนให้ครบและงานที่ implement แล้ว ไม่ได้อ้างผล native หรือการยอมรับหน้าตา โฟลว์รอบนี้ปิดทั้งสอง ticket ตามคำสั่งให้ทำครบแผน ซึ่งขยายจากแนวทางหนึ่ง ticket ต่อ session ของ tracker
