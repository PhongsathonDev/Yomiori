## Question

สถานะถูกใจและคอมเมนต์ที่ผู้ใช้สร้างเองไม่สอดคล้องกับสิ่งที่บันทึกไว้ สามจุดที่ตรวจพบ:

1. `ChapterCommentsSection.tsx` (ประมาณบรรทัด 108–111) สร้างคอมเมนต์ใหม่โดยตั้ง `likes: 1`, `userLiked: true` แต่ไม่บันทึก ID ลง liked storage ทำให้การกดหัวใจครั้งแรกเพิ่มเป็น 2 แทนที่จะเป็นการยกเลิกถูกใจ
2. `api.ts` (ประมาณบรรทัด 180–194) overlay liked ID เฉพาะคอมเมนต์ bundled/remote ระดับบนสุด ไม่ครอบคลุมคอมเมนต์ของผู้ใช้เองหรือ replies ทำให้เปิดหน้าตอนใหม่แล้วสถานะไม่ตรงกับที่เคยกด
3. `storage.ts` อ่าน persisted comments และ liked IDs ด้วย `JSON.parse` โดยไม่ตรวจรูปข้อมูล (ต่างจาก chapter/progress ที่ validate) ข้อมูล JSON ที่ถูกรูปแต่ผิด shape อาจทำให้ array operation หรือการเรนเดอร์ล้ม

ต้องแก้ให้สถานะถูกใจตรงกันทั้งก่อนและหลังเปิดใหม่ รองรับข้อมูลเดิมที่บันทึกไว้ และไม่ทำให้ข้อมูลที่เสียอยู่แล้วทำให้หน้าอ่านคอมเมนต์พัง

## Acceptance

- กดถูกใจ/ยกเลิกถูกใจคอมเมนต์ที่ผู้ใช้สร้างเองแล้วเปิดตอนใหม่ สถานะและจำนวนตรงกัน
- จำนวน likes ไม่เพิ่มซ้ำจากการกดครั้งแรก และ liked ID ถูกบันทึกจริง
- ข้อมูล comment/liked ที่ผิด shape ถูกเพิกเฉยหรือกู้อย่างปลอดภัย ไม่ทำให้จอพัง
- มี regression test สำหรับ create + like + reopen และข้อมูลผิดรูป
- storage key เดิมไม่เปลี่ยน และข้อมูลที่ถูกต้องยังอ่านได้
