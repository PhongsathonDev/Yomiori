## Question

mockup UI ทางเลือก 3 แบบใดที่ทำ UX หลักได้ครบเหมือนเว็บปกติ แต่มีหน้าตาและโครงสร้างต่างจากเว็บเดิมและต่างจากกันชัดเจนพอให้ผู้ใช้ลองเลือกทิศทางได้?

## Notes

- ผู้ใช้สั่งวันที่ 29 October 2026: เก็บตัวอย่าง v2 ไว้ก่อน แล้วเปิด ticket ใหม่ให้สร้าง mockup เพิ่ม 3 แบบ โดยให้รู้เฉพาะ UX ไม่ต้องดู UI เดิมเป็นแรงอ้างอิง เพื่อให้ได้ทิศทางที่สร้างสรรค์และไม่ลอกของเดิม
- ขอบเขต: mockup แยก 3 ทิศทาง เปิดดูได้จริงในเบราว์เซอร์ ครอบคลุม UX หลัก ชั้นวาง → รายละเอียด/สารบัญ → อ่าน → ตั้งค่าการอ่าน; มีธีมสว่าง/มืด/ซีเปีย; desktop และ mobile
- ใช้ข้อมูลนิยายจริงบางส่วน (ปก ชื่อไทยยาว เนื้อหาอ่านจริง ตัวละคร) เพื่อให้เห็นภาพ แต่ไม่ต้องต่อระบบจริงหรือทำครบทุกตอน
- ไม่ใช้เลย์เอาต์ ภาพ หรือองค์ประกอบของ [ทำตัวอย่างเว็บ v2 และปรับจนผู้ใช้พอใจก่อนพัฒนาจริง](WF-0035.md) เป็นแรงอ้างอิง; ใช้เฉพาะ UX flow และข้อจำกัดข้อมูลร่วมกัน
- ห้ามแก้ production entry point, ข้อมูลนิยาย หรือข้อมูลผู้ใช้เดิม; เก็บ mockup แยกใน `prototype/ui-lab/`
- HITL: ผู้ใช้เป็นผู้เลือกทิศทางที่ชอบ และอาจสั่งปรับบางแบบต่อ; รอบนี้ไม่สรุปแทนผู้ใช้ว่าแบบใดดีที่สุด

## Work with

- [ทำตัวอย่างเว็บ v2 และปรับจนผู้ใช้พอใจก่อนพัฒนาจริง](WF-0035.md) — ใช้ UX/ข้อมูลชุดเดียวกัน แต่ไม่ใช้ UI ของ v2 เป็นแรงอ้างอิง

## Acceptance

- มี mockup 3 แบบที่เปิดดูได้แยกกัน พร้อมชื่อทิศทางและคำอธิบายสั้น
- ทั้งสามแบบทำ UX หลักได้ครบ: เลือกเรื่อง, ดูรายละเอียด/สารบัญ, อ่าน, ตั้งค่าธีม/ตัวอักษร/ระยะบรรทัด/รูปแบบบทสนทนา
- หน้าตาและโครงสร้างต่างจากเว็บเดิมและต่างจากกันอย่างชัดเจน ไม่ใช่การเปลี่ยนแค่สีหรือมุมโค้ง
- ใช้ข้อมูลจริงบางส่วนและแสดงข้อจำกัดว่าเป็น mockup ไม่ใช่ระบบจริง
- ตรวจบน desktop และ mobile เบื้องต้น ไม่มี console error หรือภาพแตก
- บันทึกหลักฐาน/วิธีเปิดและรอ feedback ผู้ใช้ก่อนปิด ticket
