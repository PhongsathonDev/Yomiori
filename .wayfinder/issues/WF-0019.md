## Question

- Trigger: ผู้ใช้กดปุ่มแก้ไขด่วน (Quick-Fix) ที่ย่อหน้าหรือบทสนทนาใน Web Reader ขณะอ่านตอนใดๆ
- Expected behavior พร้อมแหล่งอ้างอิง: React Component ต้องเรียก Hooks ทุกตัวอย่างไม่มีเงื่อนไขและในลำดับเดิมทุกรอบการเรนเดอร์ ตามข้อกำหนดของ React (Rules of Hooks: "Don't call Hooks inside loops, conditions, or nested functions") โดยการเปิด/ปิด modal ต้องไม่ทำให้จำนวนหรือลำดับของ Hooks เปลี่ยนแปลง
- Actual behavior: ใน `reader-web/src/components/QuickFixModal.tsx` (บรรทัดที่ 23) มีคำสั่ง `if (!block) return null;` วางไว้ก่อนการเรียก `useState` 3 ตัว และ `useEffect` 1 ตัว ขณะที่ `App.tsx` (บรรทัดที่ 715–722) มีการ mount `<QuickFixModal block={editingBlock} ... />` ไว้ตลอดเวลาโดยเริ่มต้น `editingBlock = null` ทำให้รอบแรก component คืนค่า `null` โดยเรียก 0 hooks แต่เมื่อผู้ใช้กดเปิด modal และ `editingBlock` ได้รับอ็อบเจกต์บล็อก component จะข้ามเงื่อนไขและเรียก 4 hooks ส่งผลให้ React Runtime ฟ้องข้อผิดพลาดเรื่อง hook mismatch (`Expected static flag was missing` / `Rendered more hooks than during the previous render`) และ `oxlint` ตรวจพบข้อผิดพลาดระดับ Error 4 จุด
- ผลกระทบต่อผู้ใช้: ผู้ใช้ Web Reader ที่ต้องการแก้ไขคำผิด สลับตัวละคร หรือเปลี่ยนประเภทบล็อกผ่านปุ่ม Quick-Fix ประสบปัญหาหน้าต่างแก้ไขขัดข้องหรือไม่ตอบสนองตามวงจรชีวิตของ React
- สาเหตุที่หลักฐานยืนยันได้:
  1. โค้ดจริงใน `reader-web/src/components/QuickFixModal.tsx` บรรทัด 23 วาง `if (!block) return null;` ก่อน `useState` (บรรทัด 29, 30, 31) และ `useEffect` (บรรทัด 33)
  2. การรัน `oxlint src/components/QuickFixModal.tsx` พบ 4 Errors ของกฎ `react-hooks(rules-of-hooks)`
  3. การรันสคริปต์ทดสอบจริงบน JSDOM + React 19 (`.wayfinder/assets/WF-0019/repro.mjs`) ยืนยันว่าการเปลี่ยนค่าจาก `block = null` สู่ `block = object` ก่อให้เกิด React internal reconciler error ขณะที่ Control Component ที่ประกาศ hooks ไว้ด้านบนอย่างไม่มีเงื่อนไขทำงานผ่าน 100% โดยไม่มีข้อผิดพลาด
- ข้อจำกัดของการพิสูจน์: ทดสอบบน Node 24 + JSDOM + Vite SSR Loader และ Oxlint ยังไม่ได้รันบนบราวเซอร์จริงที่มี Service Worker หรือ GitHub Pages CDN

## Acceptance

- `QuickFixModal` ประกาศการเรียก React Hooks (`useState`, `useEffect`) ทั้งหมดไว้ที่ระดับบนสุดของฟังก์ชันอย่างไม่มีเงื่อนไข ก่อนการตรวจสอบเงื่อนไข `if (!block)`
- สามารถเปิดและปิด modal แก้ไขข้อความ (Quick-Fix) สลับไปมาหลายรอบได้โดยไม่มีข้อผิดพลาดจาก React Hooks
- ฟังก์ชันการบันทึกการแก้ไขข้อความ สลับตัวละครพูด และแปลงเป็นบทบรรยาย (Narration) ยังคงทำงานได้ถูกต้อง
- มี regression test ครอบคลุมการ mount ด้วย `block=null` แล้วเปิดด้วยบล็อกจริง
- รัน `npm run lint` (oxlint) ใน `reader-web` แล้วไม่มี error จากกฎ `react-hooks(rules-of-hooks)`
