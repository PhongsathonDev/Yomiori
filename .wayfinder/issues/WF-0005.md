## Question

จากอาการที่ผู้ใช้รายงาน หลักฐาน source/automated tests และแหล่งอ้างอิงคลังออฟไลน์ที่เลือกแล้ว ต้องเปลี่ยนลำดับงานใดตอนเริ่มแอป/แสดงชั้นหนังสือ/เข้าสารบัญ/เปิดตอน เพื่อให้เนื้อหาที่มีในเครื่องใช้ได้โดยไม่รอเครือข่าย และส่วนใดควร refresh ภายหลัง?

แยกกรณีไฟล์ที่ดาวน์โหลด bundled content และเนื้อหาที่ยังไม่มีจริง รวมถึง font-loading failure การนับ/สแกนไฟล์ การ refresh ซ้ำ และการรับตอนที่มีการแก้ไข กำหนดพฤติกรรมเมื่อ network ช้าหรือ error พร้อมวิธีทดสอบจำลองในเครื่อง แยกเกณฑ์ตรวจ native หลังแก้ครบ ไม่สร้าง cloud build เพื่อ unblock ticket นี้ และไม่อ้าง FPS หรือเวลาบนมือถือที่ยังไม่ได้วัด

ผลคือ entry/data-flow contract และวิธีพิสูจน์ผลที่พร้อมใช้ในสเปก ไม่ขยายเป็น redesign ชั้นหนังสือหรือสารบัญทั้งหน้า

## Progress comments

### 27 ตุลาคม 2026 — หลักฐานระหว่างลงมือแก้ตาม execution note

เอาฟอนต์ออกจาก global startup gate แล้ว โดยใช้ฟอนต์ระบบระหว่างเตรียมฟอนต์หรือเมื่อฟอนต์ผิดพลาด และรวมเฉพาะ font assets ที่ใช้อยู่ 7 ไฟล์ ชั้นหนังสือแสดง bundled content ตั้งแต่ first render; metadata local-only ไม่เรียก network บน cache miss; ตอน bundled เปิดโดยไม่รอ CDN; จำนวน bytes ย้ายไปตรวจเมื่อเปิดแผงจัดการไฟล์ แทนรอระหว่างเปิดหน้ารายละเอียด

เพิ่ม regression tests สำหรับฟอนต์ loading/error, catalog/network ไม่ตอบ, และการแสดงรายการตอนระหว่าง refresh; ไม่มีการส่ง EAS build และยังไม่อ้างว่าระยะเวลาเปิด APK จริงได้รับการพิสูจน์แล้ว

### 28 October 2026 — Concurrent refresh work

The shared JSON request layer now coalesces simultaneous requests for the same URL through response-body parsing. It releases shared work on success, failure and timeout, allowing later refreshes and retries to fetch again. Independent URLs remain independent. Typecheck, lint and 63 automated tests pass. Native startup timing and the full entry/data-flow contract remain pending; this ticket remains open.

## Resolution comments

### 28 October 2026 — Codex

ยืนยัน local-first entry flow, optional refresh และ explicit chapter update ที่เก็บฉบับเดิมเมื่ออัปเดตล้มเหลว; ผ่าน TypeScript, lint และ 66 tests

รายละเอียดและเกณฑ์รับงานอยู่ใน [Reader Android contract](../assets/reader-contract/spec.md) อิงคำสั่งผู้ใช้ให้ดำเนินงานตามแผนให้ครบและงานที่ implement แล้ว ไม่ได้อ้างผล native หรือการยอมรับหน้าตา โฟลว์รอบนี้ปิดทั้งสอง ticket ตามคำสั่งให้ทำครบแผน ซึ่งขยายจากแนวทางหนึ่ง ticket ต่อ session ของ tracker
