## Question

ภาพร่างและกติกาเลย์เอาต์แบบใดทำให้ปกเด่น เลือกเรื่องง่าย และอ่านชื่อไทยยาวได้ โดยคงโลกภาพเดิมตาม brief ที่ยืนยันแล้ว?

ฐานสนทนา: [ข้อตกลงตั้งต้น: ชั้นหนังสือที่ปกเด่นและเลือกอ่านง่าย](../assets/bookshelf-responsive/brief.md) ผลเรื่องการหมุนแยกไว้ใน [กำหนดเกณฑ์หมุนจอทั้งแอปโดยคงหน้าอ่านและตำแหน่งเดิม](WF-0022.md) และทำควบคู่กันได้

- HITL: ทำภาพร่างราคาถูกเพื่อให้ผู้ใช้เทียบและยอมรับ ไม่ implement หน้าจอ production ไม่ตัดสินความชอบแทนผู้ใช้
- เทียบมือถือจอแคบคอลัมน์เดียว แท็บเล็ตแนวตั้งหลายคอลัมน์ และแนวนอนที่ใช้พื้นที่คุ้ม; ทดลอง 2/3 คอลัมน์เป็นจุดเริ่ม ไม่ยืนยันด้วย orientation อย่างเดียว
- ใช้ชื่อ/ปกจริง รวมชื่อยาวและจำนวนหนังสือน้อย ระบุ max width, minimum card width, สัดส่วนปก, การตัดบรรทัด และลำดับข้อมูลที่สรุปได้จากภาพร่าง
- ทดสอบภาพแถบอ่านต่อเมื่อมี/ไม่มีประวัติ หนังสือไม่มีปก และข้อมูลออฟไลน์ยังโหลดไม่เสร็จ; ต้องไม่สร้างประวัติอ่านหรือสถานะครบที่ไม่มีจริง
- ระบุตำแหน่งตัวกรองหมวดเดิมและ theme switch โดยไม่เพิ่มฟีเจอร์ใหม่ ยืนยัน tap หนังสือไปหน้ารายละเอียด/อ่านต่อกลับตำแหน่งล่าสุด
- แสดงโทนสว่าง ซีเปีย และ OLED ให้เห็นความสอดคล้องก่อนสรุปภาพที่ยอมรับ ลิงก์ assets จาก ticket และเก็บรายละเอียดคำตอบใน resolution comment

## Session notes

- 2026-10-29 — OpenCode: ตรวจ frontier และ claim งานนี้เพียง decision ticket เดียว; ยังไม่ resolve และยังไม่มีภาพร่างที่ผู้ใช้อนุมัติ
- อ่านแผนแม่ ข้อตกลงตั้งต้น `CONTEXT.md` และ Work with แล้ว: เกณฑ์หมุนจอเป็นการตัดสินใจแยก ไม่ใช่ blocker ของภาพร่าง; งานยืนยันสเปกยังต้องรอทั้งสองงาน จึงไม่เริ่มหรือปิดแทน
- คงโทนและ system font ของชั้นหนังสือเดิม; ตัวเลือกภาพร่างจะเปรียบเทียบการจัดวาง/พื้นที่ชื่อ ไม่เปลี่ยนโลกภาพหรือเพิ่มฟีเจอร์
- หลักฐานที่ต้องระวัง: `BookshelfScreen.tsx` บรรทัด 131–141 ยัง fallback ไปเรื่องแรกเมื่อไม่มีประวัติ จึงไม่ควรใช้พฤติกรรมนั้นสร้างประวัติในภาพร่าง; จำนวน JSON ที่มีใน repo ไม่ใช่จำนวนตอนในเครื่องหรือหลักฐานดาวน์โหลดภาพครบ
- ส่งบริบทให้ Work with: ภาพร่างเป็นเพียงสมมติฐานเลย์เอาต์ตามความกว้าง ไม่รับรอง orientation ของ standalone APK, safe areas จริง, ตำแหน่งย่อหน้าหลังหมุน หรือการปรับ lightbox; ไม่แก้ production/config/build
- ผู้ใช้ตอบรอบเริ่มร่างแล้ว: เทียบชื่อเต็มกับ 3 บรรทัด และใช้ปกซ้าย–ชื่อขวาบนแท็บเล็ต; นี่ไม่ใช่การอนุมัติภาพร่างที่ยังไม่ได้ดู
- ภาพร่างรอพิจารณา: [หน้าเทียบ A/B พร้อมขนาดจอ/ธีม/สถานะ](../assets/bookshelf-responsive/review.html) และ [กติกาทดลอง แหล่งข้อมูล ข้อจำกัด และประเด็นรอเลือก](../assets/bookshelf-responsive/draft-notes.md) มีชื่อ/ปกจริงและ fixtures ที่ติดป้ายชัด; ยังเปิดงานและคงผู้รับผิดชอบเพื่อรอ HITL ไม่เพิ่ม Decisions so far ใน map ก่อนยอมรับจริง
- ผู้ใช้เสนอกริดปกอย่างเดียวแบบ Meb ระหว่างตรวจภาพร่าง พร้อมภาพอ้างอิง: ยังเป็นคำถาม/ทางเลือก ไม่ใช่คำสั่งเปลี่ยน UI หรืออนุมัติแทน; บันทึกข้อแลกเปลี่ยนและข้อเสนอปก+ชื่อใต้ปกใน notes แล้ว รอเลือกว่าจะร่างเพิ่มหรือไม่ ไม่ resolve และไม่แตะงานที่ต้องรอ
