## Question

ออกแบบและใช้ผลตรวจคลังซ้ำระหว่างใช้งานเพื่อลดการอ่านไฟล์ โดยรักษาความถูกต้องของสถานะตอนและการกู้จากไฟล์จริง

## Acceptance

- เปรียบเทียบกลไกที่เป็นไปได้และบันทึกเหตุผลก่อนเลือก โดยคำนึงถึงการตรวจจับการเปลี่ยนไฟล์นอกแอปและการใช้หน่วยความจำ
- ตรวจใหม่หลังแอปดาวน์โหลด อัปเดต หรือลบข้อมูล รวมถึงรูป และตรวจไฟล์จริงเมื่อเริ่มแอปใหม่
- ไฟล์เสียและ backup ยังถูกตรวจและกู้ตามพฤติกรรมที่กำหนด; การสแกนที่กำลังทำอยู่ไม่เผยผลเก่าหลังข้อมูลเปลี่ยน
- วัดจำนวน operations เทียบ baseline ของ WF-0011 และมี regression tests สำหรับการเขียน ลบ กู้ไฟล์ และการเรียกพร้อมกัน
- บันทึกข้อจำกัดและวัดเวลา/หน่วยความจำบน Android ใน WF-0008 ก่อนตั้งเป้าหมายตัวเลข

## Progress

เริ่มใช้ summary ในหน่วยความจำเฉพาะรอบที่แอปทำงาน โดยใช้ generation และ revision เพื่อตรวจการเขียน ลบ และรูป; เมื่อเริ่ม process ใหม่จะอ่านไฟล์จริงอีกครั้ง และไม่เก็บผลว่างที่อาจเกิดจาก I/O error ผล benchmark จำลองหลังสแกนคลัง 1,000 ตอนครั้งแรก การเรียก getSavedLibrary รอบถัดไปเหลือเพียงการอ่านรายชื่อโฟลเดอร์หนึ่งครั้ง (ไม่มีการอ่านไฟล์ตอน) ตัวเลขนี้ไม่ใช่เวลา Android จริง

ยังต้องตรวจการเปลี่ยนไฟล์จากภายนอกระหว่างที่แอปเปิดอยู่ และความครบถ้วนของกรณี recovery และ concurrent mutation ก่อนปิดงาน
