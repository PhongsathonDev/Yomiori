## Question

เก็บ baseline ที่ทำซ้ำได้สำหรับคลัง 100 และ 1,000 ตอน: จำนวนอ่านไฟล์/parse/ตรวจรูปต่อการเข้า Bookshelf และ NovelDetail ทั้งครั้งแรกและกลับเข้าซ้ำ รวมผลเมื่อมีไฟล์เสียและ backup แล้วแยกข้อจำกัด desktop ออกจาก Android จริง เพื่อให้ตัดสินใจเรื่อง reuse scan หรือ summary index ได้

ไม่กำหนดให้ build APK ก่อนงานนี้ ไม่ใช้ desktop timing อ้างเป็นเวลาเปิด Android และไม่แก้ไฟล์ผู้ใช้เพื่อสร้าง fixture

## Resolution comments

### 28 October 2026 — DeepSeek

เก็บ baseline ครบตามขอบเขตที่ตกลง ด้วย harness ที่ใช้โค้ด `storage.ts`/`api.ts` จริงบน filesystem จำลองในหน่วยความจำ (100 และ 1,000 ตอน, คลังละ 4 เรื่อง, เฉลี่ย 20.5 KB/ตอน, ไม่แตะไฟล์ผู้ใช้) ผ่าน `npm run benchmark:scan`

- `getSavedLibrary` สองรอบติดกันได้ operation เท่ากันทุกค่า: 1,000 ตอน = 1,000 stats + 1,000 reads + 1,000 parses + 200 illustration stats + 20.00 MB ต่อรอบ; หลังสแกนจบไม่มีการใช้ผลซ้ำ
- Bookshelf entry = 3.5 รอบของคลัง (1,000 ตอน → 3,500 reads/3,518 JSON.parse/≈70 MB) จาก trigger 4 จุด และ **กลับเข้าซ้ำได้ตัวเลขเท่ากันทุกค่า**
- NovelDetail entry = 2 รอบของคลัง (2,000 reads/≈40 MB) แม้แสดงเรื่องเดียว และกลับเข้าซ้ำก็เท่ากัน
- `mixed` (primary เสีย + `.bak`, `.bak` ค้าง, `.bak` เดี่ยว, foreign id, `.tmp`): ที่ 1,000 ตอนเพิ่ม +2.4% reads / +3.2% stats ต่อรอบ; ที่ 100 ตอนเพิ่ม +6%/+14% เพราะไฟล์ตรึงต่อเรื่องมีสัดส่วนสูงกว่า
- จำนวน operation ขึ้นกับ promise interleaving (Bookshelf 3.5–4 รอบ, NovelDetail 2–2.5 รอบ) จึงรายงานเป็นช่วงของการออกแบบ ไม่ใช่ตัวเลขคงที่ข้ามอุปกรณ์

หลักฐาน: [รายงานและตารางผล](../assets/android-scan-cost/report.md), [results.json](../assets/android-scan-cost/results.json), harness [libraryScanCost.bench.ts](../../reader-mobile/benchmarks/libraryScanCost.bench.ts); บันทึกวิธีใช้ใน [VALIDATION.md](../../reader-mobile/VALIDATION.md)

ข้อจำกัด: desktop wall time เป็นเพียง reference ไม่ใช่เวลาเปิดแอป Android; ยังไม่มี native I/O latency, Hermes/หน่วยความจำบนอุปกรณ์, เกณฑ์เวลาที่ผู้ใช้ยอมรับ หรือผลของการใช้ผลซ้ำต่อการตรวจจับการเขียน/ล้างข้อมูล — งาน APK จริงยังอยู่ที่ WF-0008 และการเลือกวิธีเป็นของ WF-0012

การตรวจ: `npm run typecheck`, `npm run lint`, `npm test` (67 tests) และ `npm run benchmark:scan` ผ่าน; ไม่ได้ build APK และไม่แก้ runtime
