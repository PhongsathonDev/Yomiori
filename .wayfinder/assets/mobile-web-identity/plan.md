# แผนพัฒนา: บุคลิกเดียวกับเว็บ จัดวางเพื่อมือถือ

สถานะ: **แผนเสนอ / ยังไม่อนุมัติสเปกหรือภาพร่าง / ยังไม่เริ่มพัฒนา UI**  
วันที่: 29 October 2026  
แผนแม่: [ปรับบุคลิกแอปให้สอดคล้องกับเว็บโดยรักษาการใช้งานมือถือ](../../issues/WF-0026.md)

## 1. เป้าหมายและหลักการ

ให้ Yomiori เว็บและแอปรู้สึกเป็นผลิตภัณฑ์เดียวกัน: ญี่ปุ่นมินิมอล อบอุ่น สงบ อ่านง่าย ใช้สีพื้นคล้ายกระดาษ สีเน้นดินเผา ตัวอักษรและช่องว่างที่มีลำดับชัดเจน ไม่ใช่ย่อเว็บเดสก์ท็อปลงมือถือ และไม่เปลี่ยนโครงสร้างแอปทั้งหมด

- ชั้นหนังสือและรายละเอียดนิยาย: เน้นเลือกเรื่อง เข้าใจข้อมูล และเข้าอ่านได้ง่าย (Operate)
- หน้าอ่าน: เนื้อหานำ UI ถอยออก ไม่แต่งจนรบกวนการอ่านยาว (Read)
- มือถือเป็นเป้าหมายหลัก; หน้าต่างกว้างและการขยายตัวอักษรต้องไม่ทำให้เนื้อหา/ปุ่มล้น ไม่เพิ่มการรองรับหมุนจอใหม่ในแผนนี้
- คงฟังก์ชัน ข้อความ ข้อมูลจริง การอ่านออฟไลน์ ความคืบหน้า และค่าที่ผู้ใช้ตั้งไว้

## 2. แหล่งอ้างอิงและข้อเท็จจริงตั้งต้น

ใช้ implementation เว็บปัจจุบันเป็นแหล่งอ้างอิง ไม่ใช้ภาพร่างที่ยกเลิกไปแล้ว:

- `reader-web/src/index.css`: โทน Muji, palette ทั้งสามธีม, font stacks, radius, shadow และจังหวะ transition
- `reader-web/src/components/LibraryView.tsx`: ชั้นหนังสือ อ่านต่อ รายละเอียด ลำดับข้อมูลและองค์ประกอบ
- `reader-mobile/src/theme/colors.ts` และ `readerStyles.ts`: ธีมและรูปแบบหน้าอ่านปัจจุบัน
- `reader-mobile/src/screens/BookshelfScreen.tsx`, `NovelDetailScreen.tsx`, `ReaderScreen.tsx` และ components ที่ใช้จริง
- `CONTEXT.md` และ [Reader Android contract](../reader-contract/spec.md): ความหมายอ่านต่อ/สถานะออฟไลน์ การเปิดเนื้อหาจากเครื่อง และ controls ที่รับรองแล้ว

การสำรวจรอบนี้เป็น **การอ่านโค้ด ไม่ใช่ผลเทียบภาพบนอุปกรณ์จริง** ตัวอย่างความต่างที่พบ:

| ประเด็น | เว็บ | แอปปัจจุบัน | แนวทางเสนอ |
| --- | --- | --- | --- |
| สีเน้นธีมสว่าง | `#b84a39` แดงดินเผา | `#b84a5f` ชมพูกุหลาบ | ใช้ครอบครัวสีเว็บ แล้วตรวจ contrast ของแต่ละสถานะ |
| พื้นธีมสว่าง | `#f7f5f0` | `#faf8f5` | เทียบพื้น/การ์ด/ขอบให้ได้ความอบอุ่นและระดับเดียวกัน |
| ฟอนต์ UI | IBM Plex Sans Thai / Plus Jakarta Sans | bookshelf ไม่กำหนด font family เฉพาะ | ทดลองฟอนต์ไทยตระกูลเดียวกับเว็บก่อนเลือกจริง |
| Dark mode | ดำถ่าน แยกระดับพื้นผิว | ดำสนิท OLED | รักษา OLED ใช้ขอบ/น้ำหนักอักษรแยกลำดับ ไม่บังคับคัดลอกดำถ่าน |
| รายละเอียดภาพ | token กลางของสี เงา มุม และ transition | สีรวมศูนย์ แต่หลาย style อยู่ในแต่ละหน้าจอ | กำหนด token และ component ร่วมให้ครอบคลุมหน้าจอ |

ค่าข้างต้นเป็นหลักฐานตั้งต้นและข้อเสนอ ไม่ใช่สเปกที่ผู้ใช้อนุมัติแล้ว ต้องจับคู่ภาพเว็บ/แอปด้วยข้อมูลและธีมเดียวกันในงานแรก

## 3. สิ่งที่เหมือนเว็บ / สิ่งที่ออกแบบเพื่อมือถือ

**ใช้บุคลิกร่วมกัน:** ครอบครัวสีและบทบาทสี ฟอนต์ UI/ลำดับอักษร สัดส่วนปก เส้นขอบบาง เงาเบา มุมไม่กลมเกินไป icon แบบเส้น และภาษาแสดงสถานะ

**ไม่ต้องเหมือนตำแหน่งเว็บ:** ความกว้างเนื้อหา การตัดบรรทัด การเรียงข้อมูล ตำแหน่ง action และการเปิดแผงซ้อน เลือกตามพื้นที่จริง safe area และการแตะ ไม่จำลอง hover บนจอสัมผัส

**คงเป็นฐาน:** โครงชั้นหนังสือปัจจุบัน การเข้า/ออกหน้ารายละเอียด การแตะอ่านต่อ แถบ capsule หน้าอ่านและชุด controls ที่รับรองแล้ว ฟอนต์/ขนาดอ่านที่เลือกได้ และ OLED black

ไม่มีคำสั่งเปลี่ยนเป็นกริดปกอย่างเดียว เพิ่ม bottom tabs หรือย้ายข้อมูลออกจากหน้าเดิม หากภาพร่างชี้ว่าจำเป็นต้องเปลี่ยน ต้องขอขยายขอบเขตก่อน

## 4. ลำดับพัฒนาและผลส่งมอบ

### ระยะ 1 — เก็บฐานเปรียบเทียบและกำหนดสเปกภาพ

งาน: [กำหนดสเปกบุคลิกร่วมเว็บและแอปจากหลักฐานปัจจุบัน](../../issues/WF-0027.md)

- เก็บ source commit และภาพเว็บ/แอปที่ใช้ข้อมูล ธีม และสถานะเดียวกัน ระบุว่าเป็น browser, emulator หรือเครื่องจริง
- ทำตาราง mapping สีพื้น/การ์ด/ข้อความ/ขอบ/ปุ่ม/สถานะ พร้อมเกณฑ์ contrast; ไม่เปลี่ยนสีตัวละครจนสับสนกับสีแบรนด์
- เสนอ typography scale, spacing, radius, icon และระดับเงาที่สัมพันธ์กัน แยก UI font จาก reader font ที่ผู้ใช้เลือก
- ทดลองความเป็นไปได้ของฟอนต์ไทยบน native: น้ำหนักจริง สระ/วรรณยุกต์ การ wrap ขนาด asset และ fallback; ฟอนต์ต้องใช้งานออฟไลน์และไม่กั้นการเปิดแอป
- เก็บฐาน startup/เข้าอ่าน/scroll ด้วยอุปกรณ์และคลังเดียวกันเท่าที่มี ไม่ประกาศตัวเลขประสิทธิภาพโดยไม่มีหลักฐาน
- **จุดอนุมัติ A:** ผู้ใช้ยอมรับสเปกบุคลิกร่วม รวมวิธีรักษา OLED และขอบเขตการเปลี่ยนฟอนต์

### ระยะ 2 — ภาพร่างมือถือก่อนแตะ production

งาน: [ยืนยันภาพร่างมือถือที่ใช้บุคลิกเว็บโดยคงโครงแอปเดิม](../../issues/WF-0028.md)

- แสดงก่อน/หลังของชั้นหนังสือ รายละเอียดนิยาย และหน้าอ่านพร้อมแผงตั้งค่าตัวแทน โดยใช้ชื่อ/ปก/ข้อความไทยจริง
- ชั้นหนังสือ: คงโครงเดิม ปรับอ่านต่อ การ์ด ปก ชื่อ และข้อมูลรองให้มีน้ำหนักชัด ไม่เปิดการออกแบบกริดใหม่
- รายละเอียด: เชื่อมภาพปก ชื่อเรื่อง ข้อมูลผู้แต่ง/เครดิต ปุ่มอ่าน สารบัญ ตัวละคร และข้อมูลออฟไลน์ด้วยระบบภาพเดียวกัน
- หน้าอ่าน: เสนอเฉพาะสี/ระยะ/เส้น/typography ของ UI ไม่เปลี่ยนความหมาย controls หรือบังคับเปลี่ยนฟอนต์เนื้อหา
- ครอบคลุม light/sepia/OLED, ชื่อยาว, ขยายอักษร, ปกหาย, ไม่มีประวัติอ่าน, loading/empty/error และสถานะออฟไลน์
- ระบุความต่างที่ยอมรับได้ระหว่างเว็บกับมือถือ; browser mockup ไม่ใช่หลักฐาน native wrapping หรือ safe area
- **จุดอนุมัติ B:** ผู้ใช้รับรองภาพร่างและ acceptance checklist ก่อนเปิดงาน production การชอบทิศทางไม่เท่ากับอนุมัติภาพร่าง

### ระยะ 3 — สร้างฐาน UI ร่วมภายในแอป

งาน: [สร้าง token และองค์ประกอบมือถือจากสเปกที่รับรอง](../../issues/WF-0029.md)

- แยก primitive → semantic → component tokens สำหรับสี อักษร ระยะ มุม และเส้น/เงา โดยคง interface เดิมเท่าที่ทำได้
- ทำ typography และองค์ประกอบใช้ซ้ำเท่าที่จำเป็น เช่น button/icon button, surface, badge, section heading และสถานะโหลด/ผิดพลาด ไม่สร้าง framework เกินงาน
- จัด pressed/disabled/loading/focus และ accessibility labels ให้ครบ พื้นที่แตะอย่างน้อย 48 หน่วย layout บน Android
- ตรวจด้วยหน้าจอตัวแทนก่อนย้ายใช้ทีละหน้า ไม่สลับ global palette แล้วถือว่าสำเร็จทั้งแอป
- ยังคงแหล่ง truth แยก web/mobile ในรอบแรก พร้อม mapping ที่ตรวจย้อนกลับได้ ไม่เพิ่ม monorepo/package หรือ runtime fetch CSS
- อ่านเอกสารตรง Expo SDK ที่ติดตั้งก่อนแตะ API (ปัจจุบัน `expo ~58.0.20` ต้องตรวจซ้ำตอนเริ่มจริง)

### ระยะ 4 — นำไปใช้ทีละกลุ่มหน้าจอ

งานกลุ่ม A: [ปรับชั้นหนังสือและรายละเอียดนิยายตามระบบภาพร่วม](../../issues/WF-0030.md)

- ใช้ token/components กับ header อ่านต่อ การ์ด หมวด รายละเอียด สารบัญ เครดิต และแผงออฟไลน์
- รักษาเนื้อหาเดิมและความถูกต้องของจำนวนตอน/สถานะ ไม่เพิ่มคำโฆษณา ไม่สร้าง progress หรือสถานะดาวน์โหลดที่ไม่มีจริง
- ใช้พื้นที่ตามความกว้างจริงและความยาวชื่อ ไม่ใช้ค่าบังคับที่ทำให้ข้อความไทยหรือ system font scaling ถูกตัด

งานกลุ่ม B: [ปรับหน้าอ่านและแผงเสริมให้มีบุคลิกเดียวกัน](../../issues/WF-0031.md)

- ใช้ระบบภาพร่วมกับ ReaderChrome, ReaderStory, สารบัญ ตั้งค่าอักษร รายละเอียดตัวละคร และ lightbox เฉพาะ chrome ที่เกี่ยวข้อง
- คง capsule ตำแหน่ง/หน้าที่ controls, Dialogue Cards, ฟอนต์อ่านที่เลือกได้ และการซ่อน controls เมื่อเปิดแผง
- ตรวจ safe area, overlay, keyboard และ TalkBack; การปรับ typography ต้องไม่ทำให้การคืนตำแหน่งอ่านผิด
- ใช้ motion สั้นเฉพาะ feedback ที่จำเป็น ไม่เพิ่ม blur/animation หนักเพียงเพื่อเลียนแบบเว็บ และเคารพ reduced motion

สองงานเริ่มหลังฐาน UI พร้อม ทำทีละ ticket ต่อ session ไม่แก้ service/cache/navigation ไปพร้อมกับงานภาพ

### ระยะ 5 — ตรวจรับและส่งมอบ

งาน: [ตรวจรับบุคลิกร่วมและพฤติกรรมเดิมบน Android จริง](../../issues/WF-0032.md)

- รัน `npm run typecheck`, `npm run lint`, `npm test` ใน `reader-mobile` และเพิ่ม regression tests ตามองค์ประกอบที่เปลี่ยน
- ตรวจภาพแบบชุด: มือถือแคบ/ทั่วไป และหน้าต่างกว้างที่สภาพแวดล้อมเดิมรองรับ ทั้งสามธีม ขนาดอักษรปกติ/ใหญ่
- ตรวจบน Android จริง: ไทยไม่ถูกตัด contrast ผ่าน ปุ่มแตะได้ TalkBack ใช้งานได้ แถบระบบไม่บัง UI; บันทึกรุ่น/OS/build/source commit/หลักฐาน
- เทียบ cold start/เข้าอ่าน/scroll กับ baseline โดยใช้เครื่อง คลัง และเครือข่ายเดียวกัน ระบุผลที่วัดไม่ได้ ไม่ถือ Jest หรือภาพร่างเป็นหลักฐานประสิทธิภาพ
- ทดสอบมีเน็ต/ไม่มีเน็ต/เน็ตช้า อ่านต่อ เปลี่ยนตอน กลับจากพื้นหลัง ฟอนต์ ธีม ดาวน์โหลดและภาพประกอบ
- เมื่อผู้ใช้สั่งส่งมอบ ให้สร้าง final APK ตาม runbook เดิม ติดตั้งทับโดยไม่ถอนแอป/ล้างข้อมูล ไม่ถือว่า push เปลี่ยน APK ในเครื่อง
- commit/push เฉพาะงานที่ผ่าน checks แล้วตามข้อกำหนด repo; ไม่ประกาศรับรองเครื่องจริงจนมีหลักฐาน

## 5. เกณฑ์สำเร็จร่วม

1. ผู้ใช้รับรองว่าวางเว็บกับแอปคู่กันแล้วเป็น Yomiori บุคลิกเดียวกัน โดยไม่ต้องเหมือนทุกตำแหน่ง
2. ทุกหน้าที่อยู่ในขอบเขตใช้สี/อักษร/ระยะ/เส้น/องค์ประกอบร่วมกัน ไม่มีสีชมพูหรือรูปแบบเก่าหลงเหลือโดยไม่มีเหตุผลที่บันทึกไว้
3. ข้อความทั่วไป contrast อย่างน้อย 4.5:1; อักษรใหญ่และองค์ประกอบ UI ตามเกณฑ์ที่เกี่ยวข้องอย่างน้อย 3:1; ไม่ใช้สีอย่างเดียวบอกสถานะ
4. อ่านชื่อไทยยาวและเนื้อหาที่ขยายอักษรได้ action สำคัญไม่หาย/ไม่ทับ safe area และมีพื้นที่แตะอย่างน้อย 48
5. startup ไม่รอฟอนต์หรือเน็ตเพิ่ม อ่านออฟไลน์ได้ และไม่มี performance regression ที่ยังอธิบาย/แก้ไม่ได้เมื่อเทียบฐานบนเครื่องเดียวกัน
6. progress/ธีม/ฟอนต์/ไฟล์ในเครื่องยังอยู่หลังอัปเดต คงความหมาย text-only/complete/bundled และ flow controls ที่รับรองแล้ว

## 6. ขอบเขตที่ไม่รวมและจุดตัดสินใจค้าง

**ไม่รวม:** เปลี่ยนเว็บ, รื้อ navigation/ย้าย router, เปิด orientation ใหม่, เปลี่ยนระบบจัดเก็บหรือ schema, ฟีเจอร์สมาชิก/community/ค้นพบ, public release/iOS certification, แปลงตอนนิยาย หรือ cloud build ระหว่างวางแผน

**รอหลักฐาน/อนุมัติ:** คู่ภาพ baseline, ชุด token จริง, UI font และน้ำหนักที่เหมาะกับ native, รายละเอียดของสามธีม, ภาพร่างแต่ละหน้า, รุ่นอุปกรณ์และค่าทดสอบ performance การตัดสินใจเหล่านี้อยู่ในงานระยะ 1–2 ไม่เดาปิดใน session วางแผนนี้

แผนนี้ไม่ฟื้น [แผนชั้นหนังสือที่ยกเลิก](../../issues/WF-0020.md) หรืออนุมัติภาพ A/B เดิม ส่วน [ตรวจ APK สุดท้ายบน Android จริง](../../issues/WF-0008.md) ยังคงสถานะและขอบเขตเดิม งานตรวจรับรอบนี้ไม่ปิดแทนกันโดยอัตโนมัติ
