# ข้อตกลงตั้งต้น: ชั้นหนังสือที่ปกเด่นและเลือกอ่านง่าย

> **อัปเดต 29 October 2026:** ผู้ใช้สั่งยกเลิกทั้งแผน รวมงานเลือกภาพร่าง เกณฑ์หมุนจอ และยืนยันสเปก คงหน้าแรกเดิม ข้อตกลงด้านล่างเก็บเป็นประวัติ ไม่ใช่คำสั่งทำต่อ/implement หรือการอนุมัติภาพร่างและการหมุนจอ งานนอกแผนนี้ไม่ถูกยกเลิกตาม

## ที่มาและสถานะ

ผู้ใช้ส่งภาพหน้าแรกบนแท็บเล็ตแนวตั้งและแนวนอน แล้วขอวางแผนด้วย Wayfinder วันที่ 28 October 2026 ผู้ใช้ยืนยันคำแนะนำสองรอบด้วย “ตามแนะนำ” ข้อตกลงด้านล่างเป็น brief สำหรับวางแผน ไม่ใช่ผลทดสอบหรือการอนุมัติภาพร่างที่ยังไม่ได้สร้าง

## ข้อตกลงกับผู้ใช้

- ปรับดีไซน์เฉพาะหน้าแรก/ชั้นหนังสือ เก็บโทนกระดาษ–ชมพู ฟอนต์และความอบอุ่นเดิม เน้นปกและชื่อ ลดเงา กรอบ และข้อมูลซ้ำ
- มือถือจอเล็กใช้รายการคอลัมน์เดียวแบบกระชับ แท็บเล็ตใช้หลายคอลัมน์ตามความกว้างที่ใช้งานได้จริง แนวตั้ง 2 / แนวนอน 3 เป็นทิศทางตั้งต้น ไม่ใช่ breakpoint หรือจำนวนคอลัมน์ตายตัว
- หนังสือแต่ละเรื่องแสดงปก ชื่อ จำนวนตอน และสถานะอ่าน/ออฟไลน์ เรื่องย่อและตัวละครอยู่หน้ารายละเอียด ไม่แสดงซ้ำทุกการ์ดบนหน้าแรก
- แตะหนังสือเปิดรายละเอียด ตัดปุ่มใหญ่เริ่มอ่าน/สารบัญที่ซ้ำบนทุกการ์ดออก
- เก็บแถบ “อ่านต่อ” เด่นด้านบน เพื่อกลับไปตอนและตำแหน่งล่าสุดทันที ไม่เปลี่ยนความหมายของอ่านต่อ
- รองรับการหมุนทั้งแอป ไม่ออกแบบหน้าอ่านหรือหน้ารายละเอียดใหม่ แต่ต้องตรวจว่าไม่ล้นและไม่สูญเสียตำแหน่งอ่านเมื่อหมุน
- คงธีมสว่าง ซีเปีย และดำสนิท OLED ตลอดจนการปรับประสิทธิภาพและแก้บัคที่ทำไว้แล้ว

## หลักฐานจากโค้ด ณ วันวางแผน

- `reader-mobile/src/screens/BookshelfScreen.tsx`: header และ scroll content จำกัดความกว้าง 800; แสดงการ์ดเรียงคอลัมน์เดียว ไม่มี breakpoint ตามขนาดจอ
- การ์ดปัจจุบันรวมชื่อเดิม ผู้แต่ง จำนวนตอน สถานะในเครื่อง ตัวละคร เรื่องย่อ และสองปุ่ม จึงมีข้อมูลมากกว่าบทบาทชั้นหนังสือใน brief ใหม่
- `reader-mobile/app.json`: ตั้ง `orientation: portrait` แม้ภาพผู้ใช้แสดงแนวนอนได้ จึงห้ามถือว่าภาพจากเครื่องพิสูจน์การหมุนตามค่าตั้งต้นของ standalone APK
- แยกทิศทางดีไซน์ออกจากความถูกต้องของสถานะ: จำนวนตอนในเครื่องไม่เท่ากับดาวน์โหลดภาพครบ และหนังสือที่มากับแอปไม่ใช่ไฟล์ดาวน์โหลดที่ลบคืนพื้นที่ได้ ตาม `CONTEXT.md`

## สิ่งที่ยังไม่อนุมัติ

ยังไม่มีภาพร่างที่ผู้ใช้ยอมรับ ไม่มี breakpoint/สัดส่วนปก/ความสูงการ์ดที่ล็อกแล้ว และยังไม่มีเกณฑ์ตรวจการหมุนจอฉบับตกลงร่วมกัน ต้องตัดสินผ่าน tickets ก่อนส่งต่อให้ลงมือจริง

## ขอบเขตการส่งมอบของแผน

จบที่สเปกพร้อมภาพร่างที่ผู้ใช้ยอมรับและเกณฑ์รับงาน ไม่ implement หน้าแรก ไม่เปลี่ยน orientation/config ไม่เพิ่ม dependencies และไม่สั่ง EAS build ระหว่าง chart map นี้
