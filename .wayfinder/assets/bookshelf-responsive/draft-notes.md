# ภาพร่างชั้นหนังสือ — ยกเลิกแล้ว เก็บเป็นประวัติ

> **สถานะล่าสุด 29 October 2026:** ผู้ใช้พอใจกับหน้าแรกเดิมและสั่งยกเลิกทั้งแผน รวมงานเลือกภาพร่าง เกณฑ์หมุนจอ และยืนยันสเปก ไม่ต้องเลือก A/B/C ต่อ ข้อมูลด้านล่างเป็นประวัติการสำรวจ ไม่ใช่ภาพที่อนุมัติหรือสเปกส่งต่อ implement งานนอกแผนไม่ได้ถูกยกเลิกตาม

งานเจ้าของ: [เลือกภาพร่างชั้นหนังสือที่อ่านชื่อเรื่องง่ายบนมือถือและแท็บเล็ต](../../issues/WF-0021.md)

## สิ่งที่ผู้ใช้เลือกเพื่อเริ่มร่าง — 29 October 2026

- เทียบชื่อเต็มไม่ตัด กับไม่เกิน 3 บรรทัดแล้ว `…` ด้วยเนื้อหาและขนาดจอเดียวกัน
- ใช้ปกซ้าย–ชื่อขวาเป็นโครงร่างแรกบนแท็บเล็ต; มือถือคงรายการกระชับคอลัมน์เดียวตาม brief
- คำตอบนี้อนุญาตให้ร่าง ไม่ใช่การเลือก A/B หรืออนุมัติสเปกสำเร็จ

## เปิดดู

- [หน้าเทียบ A/B](review.html) เป็นไฟล์ static ออกแบบให้เปิดจากไฟล์ใน repo ได้ ไม่ต้องติดตั้ง dependencies หรือรันแอป; ต้องเก็บโครงสร้าง repo เพื่ออ้างปกจริง รอบนี้ตรวจผ่าน HTTP local server ไม่ได้ยืนยันทุกพฤติกรรมของ `file:///`
- [A — ชื่อเต็ม](sketch.html?title=full) / [B — 3 บรรทัด](sketch.html?title=clamp): ใช้ความกว้างหน้าต่าง browser ปัจจุบัน
- หน้าเทียบมีมือถือ 360×800 / 800×360, แท็บเล็ต 800×1280 / 1280×800 และหน้าต่างแคบ 600×960; สีสว่าง ซีเปีย OLED และจำลองตัวอักษร 100/130%
- เลื่อนภายในภาพเพื่อดูรายการทั้งหมด; แตะหนังสือ/อ่านต่อจะแสดงคำอธิบายปลายทาง ไม่มีหน้ารายละเอียดหรือ reader จำลองที่ออกแบบใหม่
- ถ้าแท็บเล็ตถูกย่อจนอ่านยาก เลือกการดูภาพ “100%” เพื่อคงความกว้างจำลองและเลื่อนด้านข้าง; ไม่ตัดสินขนาดฟอนต์จริงจาก thumbnail ที่ถูกย่อ

## สถานะที่ตั้งใจให้ตรวจ

- ไม่มีประวัติ: ไม่แสดงอ่านต่อ/ตอนเริ่มต้น/เปอร์เซ็นต์ปลอม; หลังรู้ผลแล้วแสดง “ยังไม่เริ่มอ่าน” บนแต่ละเรื่อง
- มีประวัติ: ตอนที่ 12 ของเรื่องแรกเป็น fixture เท่านั้น ไม่ใช่ข้อมูลผู้ใช้จริง; แตะอ่านต่ออธิบายการเข้าตอนและย่อหน้าล่าสุด ไม่อ้างว่าคืนตำแหน่งจริงแล้ว
- ข้อมูลยังไม่พร้อม: แยก “กำลังโหลดจำนวนตอน”, “กำลังโหลดประวัติ”, “กำลังตรวจข้อมูลออฟไลน์”; ไม่แปลง unknown เป็นศูนย์/ยังไม่เริ่มอ่าน/ดาวน์โหลดครบ
- ปกหาย: ใช้เรื่องจริงเดิม เปลี่ยนเฉพาะปกเป็น placeholder พร้อมคำอธิบาย; การโหลดภาพล้มเหลวใช้ fallback เดียวกัน
- ออฟไลน์รู้ผล: fixture “ข้อความออฟไลน์ 1 ตอน · ภาพยังไม่ครบ” ไม่ใช้คำว่า “ดาวน์โหลดครบ”; ไม่เรียกตอนที่มากับแอปว่าดาวน์โหลดลบคืนพื้นที่ได้
- หนังสือ 1 เรื่อง: ไม่เติมหนังสือปลอมหรือขยายเล่มเดียวเต็มหน้าจอ; ว่าง: ข้อความและลองอีกครั้ง; refresh error: คงรายการที่มีและปุ่มลองอีกครั้ง
- ไม่สร้าง loading/empty/error เป็นข้อสรุปว่าระบบออฟไลน์ production ทำงานแล้ว; ปุ่มลองอีกครั้งไม่มี network effect

## แหล่งข้อมูลและข้อจำกัด

- ชื่อ/ปก/หมวดจาก `reader-mobile/src/data/novels.json`; ปกอ้าง `reader-web/public/illustrations/` โดยตรง ไม่สร้างปกใหม่หรือโหลดจากอินเทอร์เน็ต
- จำนวน 73 / 1 / 14 / 61 มาจากไฟล์ chapter ต้นทาง ณ วันที่ร่าง ไม่ใช่ `totalOriginalChapters`, runtime manifest, จำนวนในเครื่อง หรือจำนวนภาพครบ ทุกสถานะอ่าน/ออฟไลน์เป็น fixture ที่ติดป้าย
- ความหมาย “อ่านต่อ”, “ตอนพร้อมอ่านออฟไลน์”, “ตอนดาวน์โหลดครบ”, “ตอนที่มากับแอป” ยึด `CONTEXT.md`; ไม่มีศัพท์ใหม่ที่ตกลงแล้วจึงไม่แก้ glossary
- ความยาวและการตัดคำใช้ system font ของ browser เครื่องที่เปิด; ไม่รับรอง metric บน Android และ 130% ไม่ใช่ผลทดสอบ system font scaling จริง
- สี/ความกว้าง/พื้นที่แถบระบบเป็นภาพร่าง browser ไม่ใช่ screenshot native; การหมุนทั้งแอป การรักษาย่อหน้า และ overlay เป็นงานแยกใน [กำหนดเกณฑ์หมุนจอทั้งแอปโดยคงหน้าอ่านและตำแหน่งเดิม](../../issues/WF-0022.md) ซึ่งยังเปิดอยู่; lightbox เป็นบริบทประสาน ไม่ทำในรอบนี้
- ไม่เปลี่ยน mobile/web production, navigation, storage, API, dependencies, `app.json` หรือ build config; ไม่บิลด์ APK

## ประเด็นรอผู้ใช้ดูภาพแล้วเลือก

1. A ชื่อเต็ม หรือ B จำกัด 3 บรรทัด อ่านแยกเรื่องง่ายพอโดยยอมรับความสูง/การตัดชื่อได้หรือไม่? แนะนำ A ถ้าความอ่านชื่อครบสำคัญกว่าเห็นหลายเล่มพร้อมกัน
2. ปก–ชื่อและความหนาแน่น 1/2/3 คอลัมน์บนตัวอย่างจอจริงในภาพเป็นฐานที่พอใจหรือยัง โดยเฉพาะชื่อยาวและ font 130%?
3. หลังไม่มีประวัติ ซ่อนแถบอ่านต่อและขึ้นรายการทันทีตามภาพ พอใจหรือไม่? นี่เป็นข้อเสนอ ยังไม่ถือว่าอนุมัติจาก brief เดิม

ยังไม่ล็อกค่าข้างต้น ไม่ปิด ticket และไม่เริ่ม [ยืนยันสเปกและเกณฑ์รับงานหน้าแรกก่อนส่งต่อให้ลงมือ](../../issues/WF-0023.md) ที่ยังติด blockers

## บริบทใหม่จากผู้ใช้ — ยังไม่ใช่คำสั่งเปลี่ยนภาพร่าง

ผู้ใช้เสนอว่าอาจใช้กริดปกอย่างเดียวแบบ Meb พร้อมภาพอ้างอิงมือถือและแท็บเล็ตสองแนวจอ จึงเปิดประเด็นการจัดวางปกขึ้นมาเทียบอีกครั้ง ไม่ถือคำถามนี้เป็นการอนุมัติหรือการยกเลิกฐาน A/B อัตโนมัติ

- สิ่งที่น่าใช้จากตัวอย่าง: ปกเด่น พื้นที่ว่างระหว่างเล่ม และเพิ่มจำนวนคอลัมน์ตามพื้นที่ โดยไม่ต้องมีการ์ดข้อมูลหนัก
- ความต่างที่พบจาก assets ของเรา: บางปกเป็นภาพประกอบแนวนอน หรือไม่มีชื่อไทยชัดบนภาพ การซ่อนชื่อทั้งหมดจึงทำให้จำแนกเรื่องยากเมื่อจำปกไม่ได้หรือปกโหลดไม่สำเร็จ
- ข้อเสนอเพื่อสนทนา: กริดปกใหญ่กับชื่อไทยใต้ปก 2 บรรทัด พร้อมชื่อเต็มในรายละเอียดและ accessible label; คงอ่านต่อ/หมวด/ธีมเดิม ไม่คัดลอกร้านค้า คอลเลกชัน เมนูจัดการ หรือ navigation ของ Meb มาเพิ่ม
- ต่อมาผู้ใช้ให้ลองร่างกริดปก+ชื่อใต้ปก แล้วสั่งยกเลิก ticket เพราะพอใจกับหน้าแรกเดิม จึงหยุดและนำการแก้ภาพร่าง C ที่ยังไม่ commit ออก ไม่รอเลือกภาพอีก และไม่ถือกติกา 2 บรรทัดเป็นข้อตกลง

## หลักฐานตรวจภาพร่าง browser — 29 October 2026

- [ภาพเทียบมือถือ สว่าง ไม่มีประวัติ](phone-comparison.png) และ [ภาพเทียบแท็บเล็ตแนวนอน ซีเปีย มีประวัติจำลอง](tablet-comparison.png): ภาพหน้า review ที่ย่อให้เห็น A/B ไม่ใช่ screenshot จาก native app; มีการดูภาพแท็บเล็ตแนวตั้ง OLED/ปกหายระหว่างตรวจด้วย แต่ไม่ได้เก็บเป็นไฟล์ส่งมอบ
- DOM checks ผ่าน 48 กรณี: ความกว้าง 360/600/800/1280 × ตัวอักษรจำลอง 100/130% × 3 ธีม × A/B; สูตรคอลัมน์ตรงตามคาด ไม่พบ root horizontal overflow, ภาพปกเสีย, ชื่อเต็มถูกตัดใน A, ชื่อ accessible สูญหาย หรือปุ่มต่ำกว่า 48×48 CSS px; background/card ของ OLED เป็นดำสนิท
- บนมือถือ 360 ที่ browser นี้ B ตัดชื่อทั้ง 4 เรื่อง จึงแนะนำ A สำหรับเป้าหมายอ่านชื่อครบ แต่ยังต้องให้ผู้ใช้เลือกด้วยตัวเอง
- ตรวจสถานการณ์ทั้ง 8 แบบ พร้อม tap หนังสือ→คำอธิบายรายละเอียด, อ่านต่อ→คำอธิบายตอน/ย่อหน้า, Comedy filter→2 เรื่อง และวนธีม sepia→dark→light ผ่าน; ไม่ใช่ end-to-end navigation หรือ offline test
- หลังแก้รอบเดียว ตรวจภาพซ้ำและยืนยันมุมมอง 100% เก็บความกว้าง 1280/3 คอลัมน์จริงใน iframe; ตรวจเพิ่ม 800×360 ที่ 100% และ 800×1280 ที่ 130% ไม่พบชื่อเต็มถูกตัดหรือ root horizontal overflow; console error ไม่มีในรอบยืนยัน
- Node syntax checks สำหรับ `sketch.js` และ inline script ของหน้า review ผ่าน; เทียบชื่อ/หมวด/ไฟล์ปกและจำนวน chapter fixtures ทั้ง 4 เรื่องกับ repo ผ่าน
- Mechanical detector ทำงานแบบ degraded เพราะไม่มี HTML parser modules; พบเส้นเน้นข้างแถบอ่านต่อและเอาออกแล้ว ไม่อ้างผลนี้เป็น full contrast/accessibility audit
- ไม่ได้รัน mobile lint/typecheck หรือ native build เพราะไม่มีการแก้ production mobile และยังไม่ส่งมอบ ticket เป็นเสร็จ; เกณฑ์ native/font scaling จริง/rotation/progress ยังต้องตัดสินและตรวจในงานที่เกี่ยวข้องต่อไป
