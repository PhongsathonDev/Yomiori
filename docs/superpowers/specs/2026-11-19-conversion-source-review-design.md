# ตรวจต้นฉบับก่อนแปลงบท

**ทำไม:** Boyish Friend บท 11 เคยผ่านตัวตรวจความตรงทั้งที่ Markdown เหลือ 6 ช่วงข้อความ เพราะตัวตรวจยืนยันได้ว่า JSON ตรงกับ Markdown แต่ไม่รู้ว่า Markdown ขาดเนื้อหาจากต้นทาง

**ทางเลือก:** เพิ่มขั้นตอนในคู่มืออย่างเดียวทำได้เร็ว แต่ข้ามได้โดยไม่รู้ตัว ผู้ใช้เลือกเพิ่มด่านใน CLI ด้วย เพื่อเตือนก่อนทำ mapping และกันไม่ให้บทที่ยังไม่ได้เทียบต้นทางสร้างผลเผยแพร่

**พฤติกรรม:** `prepare` เตือนตอนที่สั้นผิดปกติพร้อม source ID แต่ไม่ตัดสินว่าตอนนั้นเสีย ตอนใหม่ที่จะรับรองและตอนที่ Markdown เปลี่ยนต้องมีบันทึกการเทียบต้นทางกับ source ID และ SHA-256 ที่ตรวจจริงก่อน `apply` ถ้าบันทึกขาดหรือเก่า ให้หยุดเฉพาะตอนนั้นโดยไม่ทับผลเดิม ส่วนตอนอื่นในชุดทำต่อได้ ตอนสั้นจริงหรือมีแต่ภาพจึงยังผ่านได้เมื่อยืนยันแล้ว

**การเผยแพร่:** บันทึกนี้ยืนยันว่ามีการเทียบ ไม่ใช่หลักฐานที่โปรแกรมพิสูจน์เนื้อหากับเว็บต้นทางเอง ใบรับรองใหม่ที่มีบันทึกต้องผูกกับบันทึกนั้น ให้ `audit` ตรวจแบบ offline ได้ ด่านเดิมที่ตรวจ JSON/ภาพ/ความครบของแผนยังอยู่ ไม่บังคับตรวจย้อนหลังสำหรับต้นฉบับรุ่นที่มีใบรับรองใน Git ก่อนเริ่มใช้ด่านนี้ ส่วนใบรับรองจาก converter เก่าที่สร้างขึ้นภายหลังไม่ขยายข้อยกเว้นนี้ และไม่เปลี่ยนสิทธิ์ของ legacy baseline เดิม

**นอกขอบเขต:** ไม่ย้ายไฟล์หรือโครงสร้าง ไม่แก้ scraper ต้นฉบับ ข้อมูล reader, mapping หรือแผนของเรื่องที่กำลังทำ ไม่ให้ CI ต้องเข้าถึงต้นทาง หากผู้ตรวจเข้าถึงต้นทางไม่ได้ให้ตอนนั้นค้าง ไม่บันทึกว่าตรวจแล้ว
